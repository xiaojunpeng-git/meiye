# D3-00005 未使用赠送优惠券作废：本地自测与固定验收版本

## 状态与范围

- 用户确认“券作废按照你的建议处理”；寄存/赠送领用入口明确不处理。
- 开发及本地自测完成；2026-10-09 产品经理对本固定版本确认“我测试没有问题”，并明确授权本轮 commit、部署瑞昊、push。提交前业务源码及测试指纹与固定版本一致。
- 仅补齐订单中心 V3 独立赠送优惠券作废。充值赠送、商品赠送、项目赠送原有业务路径不重写。
- 未使用且仍属于原会员、状态未变化的券可撤回；已使用、转赠、缺失、失效或关联资料异常时整笔拦截。
- 限量模板按现有发券规则恢复实际撤回数量，无限量模板不增加额度。原发券流水、原赠送事实保留，另记作废操作、事件和反向事实。

## 根因与修复

旧 `voidGift` 对 `gift_kind=coupon` 无条件抛出 `gift_coupon_reversal_not_supported`，未检查券是否已用。
本地截图样本 `ZS26100900003` 关联券 ID `16807`，读取时 `status=0,is_fail=0,use_time=0,oid=0`，确属未使用券。

新路径只读取赠送明细保存的 `coupon_user_ids_json`，校验数量、唯一性、会员、模板和直接赠送来源。
同事务先锁模板、后按券 ID 排序锁券，以未使用条件 CAS 标记撤回，恢复适用额度，再落作废操作、反向赠送事实及 `gift.voided` 事件。
作废事件追溯确切券 ID、模板 ID、恢复额度数量；不按会员/模板/时间猜测发券流水，不删除发券流水。
同键及不同键重复请求复用已有成功操作；赠送重放补齐原办理门店校验，不能借重放跨门店。
反向优惠券赠送事实记录本次作废请求、操作人和业务日，原事实保持不变。
全路径引用扫描 `gift_coupon_reversal_not_supported`：业务源码及本模块测试零引用，旧无条件拦截已删除。

## 数据架构自检

1. 权威源：独立赠送主表/明细确定本次赠券归属，会员券是核销/转赠/撤回共同检查的权益权威，券模板控制发放额度。
2. 事实粒度：一条赠送明细对应一条反向赠送事实；多张券全量校验后一次原子撤回，不合并其他赠送。
3. 生效与时间：成功事务内 `gift.voided`；反向事实 business_date 为作废日，occurred/settled/recorded 为本次真实时间，原赠送日期与快照不变。
4. 事务/并发/幂等：沿用命令外层事务及作废操作唯一身份，模板行锁、券行锁、CAS 和成功操作重放共同保护；事件合同按既有路由持久化校验，无旁路异步撤回。
5. 冲销/恢复：不删除原事实与流水，不撤销已使用券，不创建收款/退款/余额事实；有限额度恢复值可从事件追溯。
6. 权限/快照：首次作废限制原办理门店与租户；重放也限制同门店；原会员、模板、来源和数量在事务内重新核对。
7. 查询复用：沿用订单中心真实查询接口，列表仍以业务权威状态展示，未添加前端推算或新报表口径。
8. 性能/兼容：按赠送唯一身份、模板主键及券主键定点查锁；最多 999 张券，符合既有发券数量上限，不全表扫描关联、不新增索引/迁移。原商品/项目路径保留，删除仅限已替代的无条件优惠券拦截。
9. 对账/测试：核对券数量/状态/归属、额度、原赠送事实、反向事实、事件及操作；48 项真实本地 DB 检查与失败回滚、双连接锁测试见上。
