# R16 收银服务对象选中态自测

- 基线 HEAD：`d5c05999`。本项仅修复收银购物车项目行的三个按钮选中态，不改按钮文字、布局、结账字段或服务端口径。
- 原因：`本人` 的高亮只判断服务对象为本人，未判断该服务行是否选择“不算人数人次”；因此本人不计客时出现两个高亮。
- 结果：页面从服务对象与计客开关得出唯一显示选项。本人计客、朋友计客分别高亮“本人”“朋友算”；本人或朋友不计客均只高亮“不算人数人次”。不计客操作仍保留真实服务对象，结账快照继续分别提交 `serviceObject` 和 `friendCountsAsCustomer`。
- 自动化测试：新增 `tests/cashier-v3/js/cashier-service-object-choice-contract.mjs`，覆盖四种组合、三个按钮绑定、排除计客不改服务对象、结账快照字段，执行通过。`npm run build` 通过，1989 模块；仅既有大包提示。`git diff --check` 通过。
- 页面验证：在本地 18091 收银页加入项目“舒缓灸”，依次切换三个按钮，三次均只出现一个高亮；测试商品随后从购物车移除，恢复原空购物车。
- 独立旧测试：`business-source-checkout-frontend-contract.mjs` 在“充值结账必须提交正式来源更新命令”断言失败；本项未改其读取的充值组合式函数，基线 HEAD 也不含该断言寻找的命令。该失败不作为本项通过证据，也不扩大本项修改范围。
- 数据架构自检：本次只改变浏览器按钮高亮，不新增或修改业务事实、统计时点、金额、权限、迁移、事务或数据查询；真实服务对象和计客开关按原两个字段进入已有结账链路。前端源码注释新增于 `CashierWorkbenchView.vue`，说明显示互斥与真实服务对象不改写的边界。
- 文件分组：前端源码 `前端代码/cashier-v3/src/views/CashierWorkbenchView.vue`；自动化测试 `tests/cashier-v3/js/cashier-service-object-choice-contract.mjs`；验收证据为本文件。后端源码、数据库迁移、工程脚本和需提交的生成物均无。
