# R32-00001 数据中心报表双向滚动恢复

## 原因与修复

共用StoreBusinessReportView结果区table-scroll缺少overflow，计算样式为visible；表格宽度2902大于容器1473，高度1222大于容器743，外层固定布局overflow:hidden裁剪内容。不是接口未返回数据或分页遗漏。

本轮只增加该结果容器min-width:0、overflow:auto、稳定滚动条轨道及轻灰色可拖动滚动条，并防止分页栏在flex结果区被压缩。表头、合计与固定列继续沿用已有sticky逻辑，固定布局仍由后端table_layout.fixed声明。没有调整查询、指标、金额、列定义、权限、分页或导出业务代码。已有基础报表使用独立的overflow:auto容器，未扩大改动。

## 浏览器验证

真实Vue报表组件及外壳CSS，使用明确合成接口（20行、22列、42总条数）；不使用生产会话、不冒充真实金额/权限业务验收。修复前测量及截图见before-browser.json和before-*.png；修复后见after-browser.json和after-*.png。Chrome测试显式关闭默认hide-scrollbars参数，截图能看到真实横纵滚动条。

会员消费明细、合作方品项明细、市场明细三个共用入口，1515×1009及960×720视口：实际横向、纵向鼠标滚轮均可改变位置；首列、表头和合计保持固定，查询栏和分页位置不随结果滚动；末行、最右列可达，分页完整显示；空结果正常；无页面脚本错误。测试接口只用于布局，不写数据库、不调用导出生成文件。
