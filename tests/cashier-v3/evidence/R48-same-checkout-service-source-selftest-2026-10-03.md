# R48 同次销售服务来源补齐：本地自测与瑞昊发布准备

日期：2026-10-03。状态：开发与本地自测完成，待产品经理对新增固定版本确认验收；未提交新增改动，未向瑞昊写库或部署，未推送。

## 业务范围

产品经理确认历史回填仅使用同一次结账中可唯一对应的销售订单来源。纯权益核销、预约直接结束服务以及无同次销售订单的服务事实不借用原购卡销售来源。现有非空来源不覆盖。新结账中，现金购买项目和混合结账的服务事实也从同次已结算销售订单冻结来源；纯权益结账仍沿用原有同次来源选择展示，不凭原卡购买单补写服务事实。

销售订单本身没有归因类型快照，因而本次只复制一级/二级来源 ID、名称及展示名称，服务事实归因类型保持原有 `other`。这比按当前来源配置猜测历史分类更可追溯。前端“来源”列原已存在，本次无页面呈现变化。商家端 `mobile-vue3` 属独立微信小程序，产品经理明确本次仅部署瑞昊服务器与门店端，小程序不在本次发布范围。

## 数据架构自检

- 权威源：同次已结算正向销售订单的历史来源快照；服务事实为一条已完成项目的粒度。按同租户、同门店、同会员、同结账请求关联，销售订单有唯一结账请求约束。
- 时间与口径：不修改服务、销售、收款、核销或业绩事实数量、金额、业务日期及成功时间；历史来源由原销售快照补空后，按服务来源的历史筛选/统计可能增加可归因记录。
- 并发与幂等：新事实仍在原结账事务内写入；回填按批事务、行锁、逐条审计和空值比较更新，重复运行新增 0 行。保留原 `immutable_fingerprint`，新来源列不进入旧指纹重放判断。
- 历史、冲销与恢复：只补空来源并保存逐条审计，不覆盖非空预约来源；作废与反向事实、客户权益不改。独立备份、审计校验与显式回滚脚本共同构成恢复路径。
- 权限与性能：前台查询仍使用现有后端租户/门店权限；新写入仅按结账请求查同次销售订单。无新增报表查询关联或索引，回填分批执行。
- 对账：候选数量、实际修正、剩余候选、审计与服务事实字段/指纹一致性均需逐实例核对；不把本地数量当作瑞昊结果。
