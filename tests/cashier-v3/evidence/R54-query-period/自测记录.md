# 第54轮统一查询周期

## 范围与状态

按产品经理“每个页面中有用到时间段选择改成周期控件”的要求，沿用门店Vue3已有 `UnifiedQueryDateRange`，只替换查询用的日历日期区间。当前为本地实现、自测通过，待产品经理验收；没有commit、push、部署或线上写库。

源码唯一正本HEAD `df65e60a4d916f0f021ad00576314061eaeab1bf`。本轮前一项服务记录修复继续保留，最新联合指纹见 `fixed-files.json`。周期替换前的工作区文件通过Git不可变blob记录在 `baseline.json`，只记录来源，不建立第二份可编辑源码；`period-only.patch` 单独标识本次周期替换，不夹带此前共享工作区差异。

## 接入清单

- 会员详情：同一个周期入口覆盖有日期筛选的记录页签，保留各页签默认日期；有效权益/有效券/有效赠送及未完成客情仍按原规则隐藏日期，不改变持有权益范围。
- 客情任务的计划时间、跟进记录的跟进时间：各自独立草稿，保留原请求字段和查询按钮。
- 运营概况、员工看板、门店目标、客户分析：自定义起止日期接入同一周期控件，原有今天、本月、本年模式与统计口径不变。
- 工程台账：查询起止日期统一，门店范围、关键词、分页及导出字段不变。
- 经营报表：门店原周期控件保留，平台运行模式中残留的两个日期框也改为统一周期；自然月/年专用口径不降为任意日范围。
- 组合筛选：仅日期字段的between范围使用周期控件，仍保存原来的 `operator/value/valueTo`；数字区间、单点日期和精确日期时间/时分输入不误转为按日范围。
- 订单、基础报表、会员领用、商品/会员等已有周期入口、库存和费用模块继续复用现有统一控件，不重复建设。

单据业务日期、生日、预约、员工合同日期、赠送有效期、卡延期等日期录入不变。工资月份、统计年份等单个自然周期选择不属于本次两个日期框的替换。Vue2平台后台及会员端未批量修改。

## 交互与兼容

确认或清空时才回填完整日期对，日历点击、月份翻页、快捷草稿和取消不提交半个区间。各页面原有查询时机保持不变，原框架中确认周期后自动查询的入口也没有另行改变。日期始终为本地 `YYYY-MM-DD`，不做UTC转换或计算经营值。

共享控件新增可选maxDate，默认空值完全保持旧调用行为。平台日报保留原来的历史覆盖下限与“不得晚于今天”的上限；受上限约束的按日快捷本月/本年截到允许的结束日，未受限的完整自然月/年仍按既有日历边界。不能通过快捷周期绕过日期边界。

组合筛选在小屏遇到既有全局fr行轨道把内容压缩覆盖的问题，已仅在该组件重置为按内容高度排列并在原规则栏滚动，周期按钮不再被下一段遮挡。未调整其他页面布局。
