## 原因与修复

旧校验要求卡最后操作 ID 和当前版本必须等于待作废替换的原始结果。作废后卡版本递增、最后操作改成作废 ID，导致即使后续替换已全部撤回，上一笔仍被认定为发生其他变化。

新校验不回退版本、不修改历史快照，而是证明从待作废操作到当前版本的每一步：后续只能是已完整作废的项目替换及其对应反向事件。原操作号、记录键、租户、门店、幂等键、反向事件来源、`reversal_of` 与连续版本必须吻合；任一缺失、冲突或非替换卡操作均拒绝。

- 从最新有效替换倒序处理；尚未撤销的后续替换仍阻止更早作废。
- 保留原项目/目标项目次数、会员、原订单、卡状态、核销和预约保护。
- 按正向命令的 `holder → order → state → operation history` 顺序加锁；等待后重新检查成功作废账本。
- 用刚锁定的当前版本及最后操作标记做 CAS，写入新的作废版本与审计；同键/新键重复请求仍不重复返还。
- 核对链超过 1000 个版本或后续记录超过 1000 条时拒绝自动作废，不静默截断或跳过审计。
- 本轮业务注释更新文件：`CashierV3OrderCenterVoidServices.php`；测试的本地限制、回滚、规则夹具、双连接锁竞争和测试边界均有注释。

## 数据架构自检

- 权威源/粒度：每一笔原项目替换操作及其冻结来源明细；现有卡状态、权益明细和签发规则组件为当前权益权威。每笔作废一个审计及一个反向事件。
- 生效/时间：沿用事务成功的 `card.operation.voided`；作废业务日及真实发生/终态/记录时间沿用现有服务，不倒填原操作时间。
- 事务/并发/幂等：沿用网关外层事务和幂等回执，补齐共同锁序、锁后重查、连续版本证明和当前版本 CAS。异常不提交，原回执与唯一约束保留。
- 冲销/恢复：只按该笔冻结的前后余次反转；不直接设置最终 16，不重复返还已作废记录，不删除原操作或目标明细。
- 事实/Outbox：沿用现有反向业务事件写入器及 Outbox 契约，不新增现金、余额、退款、业绩事实，不重算报表。
- 维度/权限：原记录必须属于服务端租户和办理门店，保留网关作废功能权限；名称、来源及人员仍使用原快照。
- 复用/兼容：复用同一作废入口及规则权威服务，未形成第二套卡操作或修复接口。旧卡无规则投影路径和四种签发规则分别有测试。
- 性能/迁移：有限审计链、唯一键查询；无迁移、无历史回填、无跨实例配置变更。
- 对账：来源恢复、目标撤回、版本递增、原操作不变、审计与反向事件一一关联，测试结束后恢复本地基线。
