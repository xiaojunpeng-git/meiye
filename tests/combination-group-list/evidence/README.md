## 本轮新增

1. 原拼团列表按参考图展示12列，增加按拼团、组织/门店、状态、会员姓名/手机号筛选。日期和团编号保留在更多筛选中，条件点击搜索后统一提交。
2. 一团一行，后端稳定排序，每页20条；总数、列表、导出共用查询和权限。宽表内部滚动，门店与会员编号固定，分页常驻结果区底部；后台明确下发列定义和取值来源。
3. 类型按来源区分系统建档/导入会员与自行注册新客。H5 账号额外核对已证明的创建来源；无法证明的历史记录显示“待核实”，不使用今天的消费次数、新人开关推测历史身份。
4. 成团后使用整团退款，预览全部真实成员原订单及实付金额，填写原因后再次确认。原成团记录详情内不再对成功团展示单人退款按钮，原单人接口也拒绝绕过整团规则。
5. 整团同一事务校验、锁定全部真实成员订单及权益并准备退款回执；任何成员不符合则整批回滚，发起新渠道请求数为0。成功提交后逐笔调用原渠道并复用原退款领域收口，分别呈现成功、失败、待确认。已成功不重退，未知结果只查询，明确失败才可主动重试。
6. 新写入口显式校验既有拼团记录管理权限，避免旧中间件未登记路由默认放行；交易门店范围由服务端解析，跨店整团必须对全部成员订单有权限。

## 数据架构自检

- 权威源与粒度：拼团根记录一团一行；交易门店、成员身份来自对应原订单；活动原名称和期限读取既有开团快照，缺失时按列说明处理，不伪造旧已成团期限。品项读取原订单商品快照。当前门店名称/会员编号采用现有主档，未新增历史回填。
- 参加人数：后端统计团内未退款、已付款真实成员，不含虚拟名额；不由前端当前页求和。
- 时间：日期筛选使用开团时间；期限使用原期限。退款事实时间仍由原领域成功收口产生，不把申请成功当到账成功。
- 事务/并发/幂等：根记录锁串行化本团预留，按原订单ID稳定加锁；沿用订单和权益锁、订单唯一退款回执、渠道原退款号及最终领域幂等。外部渠道操作不在整团预留事务内执行；渠道不是跨订单分布式事务，部分完成保持逐笔可追溯，不能承诺对银行侧全部成功或全部回滚。
- 冲销/对账：复用原终态退款领域的余额、库存、权益和反向事实，不另建金额池，不改写原付款事实。已完成团保持成团事实，退款结果单独显示。
- 权限：列表、选项和导出使用同一门店范围；详情、成团和退款复核全部成员；整团入口显式校验管理菜单授权。
- 性能：根记录稳定分页，批量读取当前页成员、商品快照与身份来源，避免逐团N+1；真实MySQL执行计划检查通过。导出完整命中结果，上限10000条，超限明确要求缩小筛选，不静默截断。
- 迁移：无；依赖既有拼团回执、履约、开团原始快照及会员来源证据表。
