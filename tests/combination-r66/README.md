# 第66轮：拼团分享与首页分销海报

状态：本地开发与自测完成，最终固定树见 evidence/fixed-version-home.json（含首页追加修复）；旧 fixed-version.json 仅保留首阶段历史证据；尚未产品经理验收、commit、部署或上传。

## 本轮修复

拼团状态页 goods_combination_status/index.vue 的全屏加载层与分享操作层同为z-index388，加载层排在操作层后且会拦截触摸。下载失败的Promise不拒绝，导致加载长时间挂住，原相册拒绝授权分支没有失败反馈。

现将操作层固定在加载/海报展示层之上，非交互加载和展示图不拦截触摸；好友分享保留原生open-type按钮并在点击时关闭面板、取消海报生成。分享链接直接取当前拼团ID和当前会员推广ID，不依赖其他页面可覆盖的全局openPages。

海报生成复用一个在途Promise，图片/二维码读取、Canvas失败与15秒超时均可退出及重试；关闭、分享或卸载后忽略迟到结果。预览/保存会等待生成完成，不拿空路径调用原生API；保存失败和相册权限拒绝均有反馈，用户可以取消设置跳转。

## 实际资源故障

008四个 /statics/images/activity/{posterBag,posterBagInner,postertag,rmb}.png 地址HTTP200，实际为984字节HTML，不能当作图片成功。将固定素材从唯一源码中既有后端public素材按原字节打入会员端活动分包 pages/activity/static/poster，避免依赖线上缺失文件，也不增加主包图片体积。SHA及来源见bundled-assets.json。

导入商品图 /static/mall 路径复用现有域名解析，保留本地HTTP开发地址。原生getImageInfo返回的打包图片路径会去掉开头/，画布二次读取在嵌套页会找错位置；现恢复应用根路径，保留原生临时路径。

共享util.js对bargainPosterCanvas增加可选失败回调及导出失败处理，旧调用者成功约定不变。原文件混合CRLF/LF，新行保留原块行尾；空白检查采用 git -c core.whitespace=cr-at-eol diff --check，不整文件改行尾。
