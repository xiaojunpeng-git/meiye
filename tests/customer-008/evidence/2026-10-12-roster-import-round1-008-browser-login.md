# 008 第一轮导入：逐岗位浏览器页面登录补验

## 原记录的边界

`2026-10-12-roster-import-round1-008-deployment.md` 中的 33 次登录是对正式 HTTP 接口的调用，不是浏览器页面操作。此前把它概括成“真人登录”不准确。本文件记录在用户指出后补做的浏览器页面登录；操作人是 Codex，使用的是真实导入员工账号，不代表员工本人亲自登录。

## 范围和方法

- 时间：2026-10-12 约 22:34—22:36（Asia/Shanghai）。目标仅为正式 `008.cc3798.com`。
- 抽样来源：首轮导入的 28 岗位样本名单，私人文件 SHA-256 `8543f39991a3ed2d78c25f76e05e9923f7640ed180f0c05ff6332830b9cad397`。每个岗位一名已导入员工；本证据不保存姓名、手机号、密码和令牌。
- 通过 Codex 应用内浏览器实际填写账号和初始密码、点击登录，再检查可见的登录后页面、页面所示账号或人员姓名。门店端入口为 `https://008.cc3798.com/view_cashier_v3/#/login`，平台端入口为 `https://008.cc3798.com/admin/login`。这些是页面操作，区别于此前的直接接口请求。
- 区域人员在门店端登录后，页面先要求选店；选择集团组织下的门店后进入 `#/cashier`。门店人员登录后直接进入所属门店的 `#/cashier`，并检查当前显示人员。平台端检查进入 `/admin/report/group-management-dashboard`、集团看板可见且页头账号匹配。

## 结果与限制

- 28/28 个岗位的门店端页面登录通过，5/5 个区域岗位的平台端页面登录通过。区域经理的平台端第一次自动等待集团看板链接超时；重新打开登录页、重新填写并点击登录后，页面进入集团看板且页头账号匹配。没有把首次等待超时算作成功。
- 门店端每次都核对工作台的“收银”入口和页面所示人员；区域岗位核对选店步骤。末 13 个门店岗位还核对页面没有“切换门店”按钮。平台端每次核对集团看板和页头账号。
- 本轮是岗位抽样登录和页面到达验证，不等于 715 名员工逐人登录，也不等于逐项点击全部功能菜单。手机端仍沿用原记录的服务层抽样，本轮没有在手机设备上逐岗操作。
- 本轮未改线上代码、数据库和岗位权限，未触及其他实例，未执行 `git push`。
