# M008-R4-001 商品类型多选

状态：开发与本地自测完成后，以 `evidence/verification.json` 固定验收版本；待产品经理确认，不自动提交或部署。

## 本轮范围

- 商品列表：在选择方式上方增加商品类型，产品 0、卡项 5、项目 6，可多选。
- 商品选项卡：每个选项卡独立配置同样的类型条件。
- 指定商品、品牌、分类、标签与类型取交集；后端先筛选再排序分页，选品弹窗列表与总数同口径。
- 新组件默认三类全选；旧装修缺少字段时不增加限制，仅打开设置不回写旧配置；明确全不选时结果为空。
- 修正同一取数链路中选项卡刷新误读外层品牌/分类/标签的问题，对齐列表刷新时的排序字段与分类子级范围；移除该分类分支已失效注释。
- 防止切换条件/选项卡后旧异步请求覆盖新结果，手动未选商品不得退化为全库查询。

## 既有功能保护

本轮不改变进店规则、上架/删除/审核限制、价格、库存、单规格购买、统一结账、销售人、支付和权益。通用选品组件仅 DIY 显式传类型时收窄，其他业务入口保持原请求。
轮播主题、导航外边距、员工纵向横滑卡片、门店名称开关/样式四仍沿用基线，不作为本轮新增成果。

## 数据架构自检

- 权威源仍为商品目录 `product_type` 与既有商品关系；不以展示文案或分类名称推断类型。
- 配置最小粒度是一个列表组件或一个选项卡；继续保存于原装修 JSON，不新增表和客户专属判断。
- 这是目录只读筛选和已有装修配置保存，不产生销售、收款、核销、余额、业绩或报表事实，不改变统计时点、历史快照与冲销。
- 复用现有装修保存、版本和缓存失效；筛选不改写商品和订单。现有门店、可见状态条件不被类型替换。
- 没有迁移、历史回填、线上写库、真实支付、收银页面改动、push 或小程序上传。
- 本地数据库测试使用事务造数据，执行真实保存/重新读取后完整回滚并清理测试缓存；不保留测试装修、商品或关系。
