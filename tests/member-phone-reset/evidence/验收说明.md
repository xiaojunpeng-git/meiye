# 会员改号后解除微信绑定、撤销登录

本轮需求：管理员把原会员手机号改为新手机号后，原微信绑定和会员登录状态同时失效；必须重新授权当前新手机号，才能进入原会员账号。会员 UID、余额、积分、卡项和订单不迁移、不重建。仅本地开发和测试，尚未修改 PoPo 或任何线上会员资料，尚未部署、提交或 push 本轮补丁。

## 行为

1. 真正换号或清空手机号时，在 Canonical 手机号写事务里写入撤销事件，并将原微信关联历史行设为已解绑。原微信行和原会员的关联通过事件中的行 ID 保留追溯，不留可继续进入原会员的有效关联。
2. API 每次核对数据库撤销记录；旧登录即使缓存仍在也立即失效。旧凭证首次再使用时清掉该令牌桶，客户端收到原有 410001 响应后清除登录并进入授权页。离线或停留在缓存页面的设备在下一次请求时退出，不宣称可主动关闭其屏幕。
3. 新手机号授权后匹配同一原会员 UID，在同一微信写事务内验证当前号码并建立新关联。旧号码、旧 openid/unionid 回退和改号前缓存的授权资料不能重认领原会员。重新授权成功不会让旧 token 复活；改回原号码也不会复活旧 token。
4. 原号码之后走正常注册/登录规则，可拥有另一个独立会员；本轮不为它复制原会员资产。重复保存未变化号码不踢人；目标号码冲突或事务失败回滚时不产生半解绑。
5. 会员 API 登录受保护；平台、门店、员工身份和业务权限不作改动。未发生改号的历史会员凭证兼容。没有移除手机号授权或更改页面、支付和资产规则。

## 验证证据

- fixed-database.txt：从固定 Git 树只读加载全部8个 PHP 类，Reflection 逐个证明来源。实际本地 MySQL、JWT、Redis、API 解析器、微信账号选择/写入和小程序登录响应执行33项通过；只有微信服务端验证结果为测试输入，访问记录/通知事件为无副作用替身，不伪称调用真实微信授权接口。
- concurrency.txt：独立数据库连接同时执行改号与签发，证明提交后旧登录被拒绝、回滚后原登录仍可用，且签发确实等待会员行锁。仅提交命名受控的本地测试夹具，结束后按所有权清理。
- client.txt：执行原会员端 MP 请求处理和 toLogin 实现，410001 后实际走 LOGOUT 与授权页；无前端源码修改。
- canonical-regression.txt、preserved-regression.txt：原手机号唯一身份合同、头像保存数据库回归、此前8项登录跳转流程回归。静态语法、SQL 幂等、查询索引验证另见 verification.json/lint.txt。
- 主数据库夹具全事务回滚，未留下伪造会员或资产事实。没有真实资金、真实手机号授权、生产数据写入或线上断登测试；小程序真机完整改号流程需部署获批后再验收，不把本地测试称为线上验证。

## 数据架构自检

权威源为 user.phone＋Canonical 手机号唯一身份映射，撤销状态为新增 member_phone_login_reset。事件粒度为某会员一次实际换号/清号，随机撤销证明只承担认证有效性，不是收银业务快照或业务版本。created_at 是撤销事务发生时间，现有手机号身份审计保留操作来源；不生成经营统计指标或财务事实。

Canonical 原号码/新号码唯一锁和会员行锁继续有效；撤销、解绑、号码变更共用事务。签发使用同一会员行锁并校验本次微信认证取得的证明，防止登录认证与改号交错。重复同号不产生事件；失败全回滚。已有资产、订单、核销历史不改写，无历史回填，后续改号再产生新撤销事件。新增表查询以 (uid,id) 命中最新记录，不遍历 token 桶、不跨客户扫描 Redis，也不清全站缓存。
