# MOHE-AI-00004 · 可靠异步执行验收记录

本文件记录“可靠异步执行＋现有任务恢复＋分段耗时分析”的实施与验收边界；它不替代固定 Git 版本、产品经理验收或逐实例发布授权。

## 运行模型

1. 创建或澄清成功时，必要的最少输入先加密写入实例私有临时存储，再与 Run 的待派发状态一并提交；Redis 队列只接收 Run 引用。旧 `/execute` 仅作为幂等兼容触发器，不能重复执行。
2. 专属 Worker 在领取后重新读取可信账号身份与当前数据权限；不会复用 HTTP 登录环境或旧权限快照。
3. 监督器负责未领取任务补派、截止任务终止、确认已经停止的本机 Worker 回收，以及加密临时输入清理。已领取工作不会自动从头重跑；结果未知保留 UNKNOWN 诊断，迟到 Worker 无权发布结果。
4. 设备端在刷新、断网或页面恢复后继续按 Run 版本轮询；明确停止、关闭和卸载取消继续有效。旧请求的回包必须匹配当前任务及页面生命周期，不能覆盖新对话。

## 实施前置与实际验收

- 每个实例必须独立执行 `后端代码/database/upgrades/2026-09-15-魔核AI可靠异步执行/01-执行消费者与耗时.sql`，核对 InnoDB、主键和两组索引。
- 必须由该实例的进程管理器分别常驻 `scripts/run-mohe-ai-execution-worker.sh` 与 `scripts/run-mohe-ai-supervisor.sh`。生产实例使用 `scripts/install-mohe-ai-systemd.sh` 安装两项独立服务；配置开关本身不表示可用，实时消费者与监督器心跳才允许接纳异步任务。
- 验收要保留一次真实页面记录：创建、同话题追问、场景切换、澄清继续、刷新恢复、停止、重复提交；并额外执行 Worker 重启、Redis 不可用和执行期间权限变化测试。
- 运行诊断按接纳、排队、模型、Reader、交付分段记录；以相同问题样本比较中位数、较慢请求耗时和成功率。快速返回“已接收”不等于最终答案变快。

### 本次回归与剩余验收缺口

- 本次重跑通过：`async-execution-state-contract.php`、`async-execution-envelope-contract.php`、`browser-lifecycle-race-contract.mjs`（3 项）。本机数据库观察到消费者和监督器心跳，均在约 1 秒内更新；这不替代生产常驻及重启恢复测试。

## 2026-09-15 第二次优化：完整答案测量与重复输入削减

本次把两个尚未完成的工程缺口落实为可测代码，未据此宣称已经提速：

1. 浏览器在答案已实际渲染后，只向已签名的 Run 回传一个 `client_elapsed_ms`。它没有问题、答案、身份、指标或时间戳；服务端只接收首个 0–300,000ms 的值，作为 `browser_observed` 分位数样本。它不改变 Run 状态、权限、结果、队列调度或任何业务数据，重复回传保持幂等。
2. 同步兼容路径也记录与异步完全相同的“接纳→发布”操作段，因此 `compatibility` 与 `async` 都可分别查看服务端答案耗时、执行耗时、单问题模型总耗时，以及浏览器观察到的完整答案耗时。浏览器耗时是客户端报告的体验指标，不能替代服务端健康判断。
3. 两阶段模型链路保持不变：第一阶段继续使用完整的用户意图理解 Skill，且不接收能力目录；第二阶段接收已经过契约校验的结构化理解结果。第二阶段不再重复发送同一份语言理解 Skill，仅保留业务 Skill 与原有绑定安全约束。这是减少重复上下文输入，不是把用户表达改成固定指标或合并模型调用。
