# 魔核 AI 现金查询规模验证（2026-09-08）

## 结论

隔离 MySQL 5.7.44 实际执行通过：84 项（此前 82 项正确性/导出链路回归 + 2 项规模/迁移验证）。本次未连接本机业务库、客户数据库或模型，未修改业务金额、权限与事实写路径。

新增来源守卫索引被实际查询选中；130 店、10 万收款事实、5 万补收主表、1 万作废操作的 28 天范围，4 个真实数据库连接各执行 3 轮“汇总 + 每日分组”，12 个结果均严格等于 9,000,000 分，作废补收不计入。

## 可重复入口

`bash tests/mohe-ai/run-query-mysql.sh --scale`

仅创建任务专属 Docker MySQL，随机密码仅环境变量/管道使用，不读取应用 `.env`，不写凭证或真实数据；退出自动删除该容器和匿名卷。普通入口不加 `--scale` 时仍只跑原有小规模业务回归。

宿主 ARM 仿真运行 amd64 MySQL 5.7，64 MiB InnoDB buffer pool。曾出现启动退出 139，失败未运行 SQL；测试脚本现可在进程退出时立即停止。最终成功运行不隐去该环境限制。

## EXPLAIN

- 收款主表：本次全覆盖范围选择 `ALL`，估计 99,490 行；查询确需汇总几乎全部夹具事实，不用事实行 LIMIT 伪造速度。
- 补收作废守卫（前）：`idx_fixture_tenant`，`Using where`，仍需按来源类型/ID/状态过滤。
- 补收作废守卫（后）：`idx_ai_cash_source_guard`，`ref`，`Using index`，使用租户、来源类型、来源 ID、成功状态完整定位。
- 补收主表：`idx_fixture_repayment` / `ref`；原充值作废与父充值作废均使用既有 `idx_source` / `ref`。

夹具仅镜像相关既有索引前缀，字段宽度、磁盘、缓存命中、真实销售分摊量及业务写入竞争均不等同于生产。
