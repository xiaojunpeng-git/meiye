# 魔核 AI 长期回归测试用例（第 22—42 轮）

> 版本日期：2026-09-25
>
> 文件路径沿用原名，避免既有方案与证据链接失效。
>
> 覆盖范围：经营问数的自然语言理解、注册指标绑定、统一查询、上下文、回答呈现、Excel 异步任务与安全失败。
> 用例性质：这是长期验收设计，不是某一次线上部署的通过证明。每条用例均须按当前固定版本重新执行并留存结果。

## 1. 重组原则

1. 同一能力只保留一个主用例；日期、数量、对象替换作为该用例的变体，不再拆成多条重复用例。
2. 第 30—42 轮产品经理实际提出且曾答错、答不出或超时的问题，均保留为“真实问题回归”锚点；原句不改写成代码规则。
3. 预期由“对象 + 注册指标 + 时间 + 结果形态”定义，真实姓名、门店、金额和人数只在当次真人验收中对账，不写死在用例内。
4. 确定性快捷路径仅可在注册表能唯一证明对象、指标、操作与日期时使用；不确定的问题仍必须由模型理解或请求澄清。

## 2. 通用前置与判定

| 编号 | 要求 |
| --- | --- |
| P-01 | 使用同一固定源码版本的后端、执行 worker 与平台前端；真人测试使用已登录的授权账号。 |
| P-02 | “今天、本月、最近 30 天”等相对日期由服务端 `Asia/Shanghai` 可信业务日解析。 |
| P-03 | 对账以同权限、同范围、同期间、同注册指标的统一 Reader/报表为准；前端和模型不得自行计算经营值。 |
| P-04 | 真人测试保留问题链、统计日期、页面用时、Run 状态、回答形态和对账结论；不得删除失败 Run 或把夹具通过冒充真人验收。 |
| P-05 | 答案必须显示统计期间；金额面向用户按元整数展示，内部计算与导出仍保持分精度。 |

### 通过与失败判定

- **查询成功**：对象、指标、范围、日期、排序/条件及结果形态均正确，且与统一 Reader 对账一致。
- **安全失败通过**：未完整理解或无完整数据能力时，不查询删减后的问题、不伪造 0 值/名单，并说明真实限制或可执行的下一步。
- **性能通过**：确定性问题不无故进入模型；模型问题受总等待预算限制；Excel 生成不得阻塞屏幕答案。

## 7. 不应误判为通过的情形

1. `member_days_since_last_visit` 的历史服务覆盖未完整时，90/120 天未到店问题只能安全提示，不能记为成功数据验收。
2. 模型超时后的安全提示只说明失败处理正确，不代表原问答成功。
3. 未明确且会实质改变结果的对象、指标、范围或条件，不能为了“首答完整”而猜测。
4. 本文不授予部署、生产数据库操作或推送权限；这些操作仍须按固定版本、目标实例、备份/回滚与真人验收执行。
