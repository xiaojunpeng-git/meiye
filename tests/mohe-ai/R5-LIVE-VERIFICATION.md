## 发现并处理的问题

1. **前端开发服务仍提供旧协议产物**：新请求被安全拒绝并要求更新。核对源目录后重启本地开发服务，确认 v2 引导 UI 与请求恢复；没有放宽服务端版本校验。
2. **平台一次取数后的通用失败**：当时没有足够的异常明细确认其独立根因；对齐驻留版本后同问成功，保留这条观察，不把重试成功当作原异常已被精确归因。
3. **平台另一请求停在 RECEIVED**：MySQL 最近死锁记录的时间与失败 Run 相符，两个事务均先 `INSERT IGNORE` 获得重复键共享锁，再以 `FOR UPDATE` 升级独占锁，造成死锁。修复 `AiRunStore`，MySQL 改用不改变计数的 upsert 直接取得独占锁；保留事务、权限、幂等与槽位检查，不用重放模型调用掩盖问题。SQLite 路径保持不变。
4. **旧 MySQL 导出夹具版本未同步**：夹具使用当前能力哈希但缺少 v2 引导版本，正确触发 `AI_CAPABILITY_CHANGED`。为夹具补齐当前 v2 快照，未弱化生产版本门禁。

首次隔离 MySQL 容器未就绪即退出；任务容器已由脚本清理，重跑后正常。本机存在 amd64 镜像模拟提示，不将其列为业务故障。
