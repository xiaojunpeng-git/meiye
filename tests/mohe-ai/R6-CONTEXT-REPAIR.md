# 第 6 轮 · 模型理解与输出衔接：上下文机制修复

当前工作基线 HEAD：`9b113777f56ca1be3624e29d76d6a0249b6190f2`。本说明描述未提交的第 6 轮实现和本地自测；不表示产品经理验收、部署或推送。

## 目标与结果

每个新问题都由模型理解完整自然语言；只有已验证的上一轮查询才可作为候选上下文。模型不能因为少输出一个字段而让服务端猜测“沿用”。

- 新增唯一入口 `IntentContextMerger`：接收已验签、已重放并按当前权限复核的前一查询和模型 Delta；不读取客户原话、不解析关键词、不保存会话、不计算指标。
- 模型输出契约升级为 `intent-result-v3`。有前文时必须完整声明 `metric_codes`、对象、业务筛选、门店范围、期间、查询方式、排行方向、排行数量和范围的 `inherit / replace / clear / pending` 决定。
- 合并器只保留明确 `inherit` 的前文；`replace` 只采用同一模型输出中的新语义；`clear` 显式移除。模型声明 `pending` 时，服务端收集每一项待确认条件；每项选择都会更新同一份待执行计划，全部确认后才执行。门店范围、业务筛选和对象的清除会同时从最终计划移除旧约束；指标、时间、展示方式和排行参数可从已登记选项或日期控件重新确定。排行的“前 1”在只改时间、数量或其他字段时不再被改成默认前 5。
- 展示方式选项由当前对象和已选指标的注册能力生成。例如会员现金业绩仅登记排行时，追问只会提供“排行”；伪造未登记的“汇总”选择会停留在当前确认步骤，不会进入执行后失败。
- 指标选项同样由当前对象和展示方式的注册能力生成。旧指标在新对象下不可执行时，不显示“沿用上一轮”；伪造未登记的指标选择不会进入执行。
- 确认更换对象后，服务端先将待执行计划切换到新对象，再生成剩余选项；旧对象不支持的“沿用上一轮”选项不会保留。
- 选中的人员/岗位只在对象 Delta 及筛选 Delta 明确继承时，才以当前授权目录重新绑定；失效或冲突停止，不替换成别的人员。
- 如果模型将对象替换为新对象、却把上一轮业务筛选声明为继承，系统先展示“按本次对象继续查询”的确认步骤；确认前不执行，也不静默删除旧筛选。明确替换门店时，当前问题中的门店名称只用于当前授权门店目录绑定，不能退化为全范围查询或多余门店选择。
- 格式恢复最多一次，只要求模型重新输出完整 JSON，不能由服务器补充指标、对象、期间、排行或任何承载业务意图的值。
- 模型把一个不适用的可选排行字段写成整体 `null` 时，将其视作字段未提供；只有方向和数量同时为 `null` 且没有任何额外键时才适用。半缺或夹带未知键的排行仍拒绝，服务端不会补方向或数量。

## 删除的旧执行路径

删除 `execution/AiFollowupQueryPlanner.php`，并移除 Gateway 的旧投影分支、`inheritContext`、本地选择兜底和旧执行调用。配置未启用安全自然语言契约时，入口返回 `AI_MODEL_CONFIG_UPGRADE_REQUIRED`，不会退回关键词/正则/本地场景匹配。

保留 `AiModelInputProjector` 仅用于历史输入兼容、管理预览及离线夹具；它不再参与任何 AI Run 的解释或执行决定。
