# 魔核 AI 第 4 轮：动态能力发现与受控编排

## 本轮目标

魔核 AI 不以报表页面、固定提问样例或固定指标候选作为能力边界。它先从统一数据底层的**已登记指标定义 + Reader 能力合同**发现当前登录人可用的能力，再按对象、操作、筛选粒度和权限编译已注册 Workflow。

本轮仅消费已存在的 11 项 V3 注册指标；不修改事实表、Reader 取数、指标公式或历史数据，也不恢复冻结的顾客生命周期类指标。

## 运行链路

```text
用户问题
  -> 本地语义投影（只识别对象 / 指标槽 / 时间 / 查询形态；不算数）
  -> 当前账号能力快照
  -> AnalysisCapabilityCatalog（指标 + 对象粒度 + 操作 + 完整筛选合同）
  -> 单步受控引导（人员结构 / 已登记指标 / 时间 / 排序）
  -> AiRegisteredPlanCompiler
  -> 已注册 Workflow / Tool
  -> 统一 Metric Reader + Evidence 校验 + 确定性答案
```

模型只能从服务端给出的能力标识中理解意图；不能生成指标、表名、SQL、DAO、公式、对象引用或 Workflow 图。前端选择和用户条件只能缩小当前报表权限。

## 本轮变更

1. 新增 `AiCapabilityGuidanceCatalog`：对 `AnalysisCapabilityCatalog` 做当前账号的权限投影。候选必须同时匹配指标、对象粒度（门店/人员）、查询形态、筛选合同与 Reader 就绪状态。
2. 删除“服务业绩 / 收入 / 卖了多少”各自固定到某几个指标的分支。它们现在只表示“指标尚未明确”，候选来自当前注册能力；“以上都不是”受控停止，不删除原条件、不猜测替代指标。
3. 人员问题（如“今天做得最好的技师是谁”）先以当前有权查看的真实岗位/人员结构进行单选；未指定评价标准时，再从可用于排行的人员指标中单选。岗位名不能唯一命中时不模糊绑定。
4. 原始计划不再携带可编辑节点、调用预算或预计算哈希；它直接标识 `wf_performance_{query_shape}`，由 `AiRegisteredPlanCompiler` 从版本化注册表重建不可变节点、预算、依赖版本和哈希。
5. Skill 从“经营结果 / 门店比较”两条初始场景收敛为 `skill_registered_metric_analysis`。该 Skill 是交互边界而非问题白名单；可执行范围仍由每次运行的能力快照决定。

## 关键边界

- 没有合法能力：明确停止，不退化为“全店/全部人/默认指标”查询。
- 人员、岗位、分类等对象候选先经过当前账号数据权限；候选本身不授予权限。
- 一个 Run 只可执行编译后的登记节点；最多调用、超时、取消与 Evidence 约束仍由既有 Run/Compiler 负责。
- 后续教培、标准财务等模块只需注册新的字典定义、Reader 合同和对象合同；不新增问题场景或修改 AI 核心编排器。

## 本地自测

- `semantic-guidance.php`：100 项，覆盖动态候选收缩、通用停止项、具体 Workflow、日期及条件边界。
- `personnel-analysis.php`：43 项，覆盖真实人员结构选择、指标不猜测、按查询形态过滤候选、权限和编译约束。
- `registry-execution.php`：85 项，覆盖通用 Skill、注册 Workflow、不可变编译图及 Tool 依赖。
- `gateway-r5-guidance.php`：102 项，SQLite 状态机 + 合成事实/模型的端到端受控引导与执行回归。

以上均为本地合同/合成数据验证，不等同于真实客户数据或产品经理验收。
