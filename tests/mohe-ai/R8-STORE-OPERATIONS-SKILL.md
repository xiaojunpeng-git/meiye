# 魔核 AI 第 5 轮：门店运营 Skill

## 目标

将魔核 AI 的运行时业务边界固化为一个可阅读、可校验、可追溯的门店运营 Skill。经营者可从收款、退款、实际业绩、消耗、服务、门店、人员、项目、产品、会员、合作品项和产品使用等问题进入；每次实际执行仍由统一数据底层的注册指标、对象关系、读取合同和当前账号权限决定。

## 运行来源

`后端代码/app/services/ai/skills/store_operations/SKILL.md` 是唯一的门店运营 Skill 原文。`AiSkillDocument` 严格校验其嵌入的 JSON 合同，并将正文哈希写入注册表、能力快照与编译计划依赖版本。Markdown 不能声明 SQL、DAO、指标公式、Tool Handler、权限或 Workflow 图。

`AiBusinessManifest` 只从该受控文档读取业务名称、目标、经营域、必要事实、歧义类型、完成条件和反例；Tool、Workflow 节点、预算、权限合同、证据校验与确定性渲染继续由受控 PHP 注册表定义。

## 当前门店运营域

1. 整体经营：收款、退款、实际业绩、消耗、销售、完成服务和活客。
2. 门店与组织表现：门店、组织的排行、趋势和两期对比。
3. 人员与岗位表现：销售贡献、劳动贡献和已授权人员排行。
4. 项目经营表现：项目的销售、完成服务、消耗和期间变化。
5. 产品与商品分类表现：产品、商品分类与客户自定义分类表现。
6. 会员经营：高消费会员、经常到店会员及单会员近期表现。
7. 合作品项经营：商品分类中启用合作方配置的外部合作产品、项目及其销售、服务、消耗表现；不把合作方当成获客渠道或客户来源。
8. 产品使用与库存：售卖、领用、实际耗用和库存。

后五类不是“文档一写即可查询”。当前实例只有已登记并已就绪的 V3 指标及门店/人员对象关系可执行；项目、产品、库存、会员和合作品项能力在对应对象合同接入后才能进入候选。

## 验收要点

- Runtime Skill 文档的合同、版本与完整正文哈希被编译计划冻结。
- 所有汇总、趋势、排行、对比及指标解释 Workflow 均绑定 `skill_store_operations`。
- 管理端能只读查看实际运行的 `SKILL.md`。
- 旧 `registered_metric_analysis` 管理文档 rebase 后，保留可编辑的名称、目标和常见问法，不能继承旧执行声明。
- 同一登录人、相同期间、相同筛选及权限下，结果仍由统一 Reader 与 Evidence 服务校验。
