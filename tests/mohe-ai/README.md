# 魔核 AI：本地合同与指标对账测试

沟通编号：MOHE-AI-00001。此目录同时覆盖魔核 AI 运行合同、统一指标注册层、页面投影回归与可选的本地真实数据只读对账。

## 执行

在源码根目录运行 `bash tests/mohe-ai/run-all.sh`。可用环境变量 `MOHE_TEST_PHP` 指定 PHP 可执行文件。

测试加载真实合同类及必要的既有类声明，不启动 ThinkPHP，不读取 `.env`，不连接数据库、Redis、SiliconFlow，不启动 Worker、不创建导出文件。

| 模块 | 测试 | 本批次覆盖 |
|---|---|---|
| 统一指标与报表能力登记 | metric-registry-contract.php | 原子/派生分类、维度与时间语义、唯一注册表、Reader 策略分派及执行就绪状态 |
| 运行预算与容量策略 | runtime-contract.php | 默认180秒/最高300秒、澄清冻结、循环与调用上限、接纳判断、容量错误归类 |
| 共享导出来源合同 | export-source-contract.php | REPORT/AI来源不可变、派生分区、双层query、归属和最早到期 |
| 模型计划输入边界 | plan-contract.php | 严格JSON、重复键、候选归属、日期与指标限制、禁止DAO/公式/未绑定范围 |

运行脚本还对新增 PHP 做语法检查，并执行既有集团报表稳定性、订单中心统一导出两组回归。`bash tests/mohe-ai/run-query-mysql.sh` 使用可丢弃 MySQL 夹具验证金额、退款、作废、服务完成、人员/项目排行和活客边界。

本地真实业务数据对账不默认运行。[metric-reconciliation-local-live.php](</Users/xiaojunpeng/Desktop/魔核/美业/美容源码/tests/mohe-ai/metric-reconciliation-local-live.php>) 需要显式的本地只读确认值和预期数据库标识，对比 11 个注册指标与 G/C/S/E/M 五条当前页面路径；金额到分、数量到个。脚本自建 PDO 只读事务不能覆盖 ThinkPHP 的独立连接，因此结果只记为当前页面冒烟比较，不伪称整个查询在同一只读事务内。脚本不输出姓名、会员资料或密钥。

## 边界

- 指标注册不是权限授予；每次查询仍必须重建当前登录人的报表数据权限。
- 本轮只收敛 V01–V11，不将 V12–V20 或 legacy 主表指标临时接入 Reader/AI。
- 已注册的金额、数量和人数指标都由同一读视图、证据和确定性回答链路提供；Excel 导出携带“数值 + 单位”，不把数量伪装为金额。
- 本地契约和真实只读对账通过不等于产品经理验收、commit、部署或 push。

## 继续验收门禁

1. 当前 129 项仅是单门店、当前代码水位的页面冒烟，不能表述为“全部原页面基线一致”。产品经理验收时，`customer_active` 必须单列连续不少于 30 天、至少两店的旧页面基线；旧页面基线从本轮改造前的固定提交实际运行取得，旧/新读取必须保留同一数据水位证据，并记录旧查询生成的 SQL，避免把差额误归因于跨日/跨店去重。当前样本若跨店重复会员为零，应如实记录“本窗口跨店差异为零”，不以等待其他实例或历史数据处理挂起。
2. 数量类导出与 Evidence 契约独立完成后，才能将 V10/V11 的 `ai_query_ready` 置为 true。
3. 保持项目验收门禁；本地自测不替代产品经理验收，不授权 commit、部署或 push。

`active-customer-baseline-local-live.php` 专用于活客基线：同一脚本在基线提交以 `legacy` 模式读取旧统一报表、员工看板、移动数仓，在当前源码以 `reader` 模式读取注册 Reader；每次均记录服务事实与作废事实的前后聚合指纹。旧员工路径额外记录有效服务行数、去重会员数及实际生成 SQL，用于判定旧页是否把服务行数误作活客。它只在显式本地只读授权、目标数据库 UUID 和数据库名同时匹配时运行。

代码语法按PHP7.1可用特性编写；本批实际执行环境为PHP8.5.8，不能据此声称生产PHP版本兼容性已验证。
