# D3-00003 薪资统一读取当前商品分类

## 产品确认与范围

2026-10-09 产品经理明确要求“关联商品的分类，商品有分类就有，没有就没有”，并对历史记录全部按当前商品分类重新归类的影响回复“是”。这是薪资报表分类维度的明确变更，不修改历史业务事实、日期、金额或人员分配，不扩展其他经营报表。

销售、服务、退款只负责定位实际商品 ID；商品分类统一由 `salaryCurrentProductCategories` 读取。规格 ID 必须先关联实际商品；销售商品和服务项目直接使用权威事实中的商品 ID；卡项仍按卡内项目 ID 和原有金额权重拆分，不能使用卡项外层分类。明确关联的平台父商品可提供现行继承分类；不按名称、其他门店同名商品或旧分类快照猜填。

有有效当前分类则显示两级路径，没有则普通明细留空（页面既有空值样式显示 `-`），对应现金金额在汇总/分类下钻中进入未分类。旧分类快照保留供审计，但不再决定这两张薪资报表的分类。分类配置调整会改变历史分类归属，员工金额总额保持不变。

## 架构自检

- 金额、项目数、客户指标、员工分配、生效状态、业务日继续读取统一事实及共享客户指标服务，粒度和记账时点不变。
- 当前分类是经产品确认的查询维度；原销售、服务、卡内分摊、退款及业绩事实不写回。测试仅在本地事务内暂改商品配置，并在 `finally` 中回滚及读回核对。
- 列表、汇总、精确下钻、完整导出投影共用该后端读取器；金额继续按分精度计算，页面使用既有整数元格式化。
- 商户及门店范围在事实入口约束，服务事实和原销售定位均受范围限制；规格、商品归属、历史卡项目与持卡人关联再次核验。不能跨店借分类或通过同号商品 ID 误关联规格。
- 卡项继续使用历史卡内金额权重，分类 ID/路径改读当前组件商品，整数分余数规则保持；分类调整只改变分类金额归属，不改变员工总额。
- 没有实际商品 ID、无有效配置、商品被删除、分类断链/循环时留空，不恢复旧分类名；没有可追溯卡内分摊或项目 ID 的卡退款也不能用卡名猜填。
- 不增加业务写命令、事件、Outbox 或迁移，因此并发、幂等及冲销写入契约不变；跨日终态冲销仍由原统一查询规则排除。
- 商品与关联按 300 个 ID 批量查找，无逐员工逐行商品查询。EXPLAIN：商品查询使用 `PRIMARY` 范围索引；所选规格与实际商品关联均使用主键常量读取。本地 193 行完整明细单次查询约 246 ms，仅为本地样本，不冒充线上性能验收。
