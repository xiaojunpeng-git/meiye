## 发现与修复

### 会员消费明细在有销售分摊数据时报错

页面复现 `Unknown column 'cashier_v3_payment_sale_allocation_fact.payment_fact_id'`。原因是相关子查询使用逻辑表名作为关联别名，而实际 SQL 表名带数据库前缀。修复为显式 `allocation` 别名，并向统一作废过滤器传递该别名。

生产代码仅改 `后端代码/app/services/report/StoreUnifiedReportServices.php` 的 `decorateMemberConsumptionRows`。补充注释说明数据库前缀与关联边界，没有改收银结账、金额计算或其他前端行为。

原本随机选择首个门店的查询冒烟可能落到空结果，跳过这段逻辑。现增加指定门店参数，并要求会员消费明细实际返回数据，避免“空表通过”掩盖错误。
