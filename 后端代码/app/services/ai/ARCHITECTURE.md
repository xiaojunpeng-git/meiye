# 魔核 AI 模块边界

本目录按职责组织，而不是按页面、入口或某一条用户问法组织。人员数据权限、统一指标 Reader 与注册表是唯一的数据和执行边界；不同入口只提供认证后的人员身份。

## 目录职责

- `skills/`：模型可读的业务与意图指导原文。Skill 只写专业理解和边界，不写 SQL、指标公式、权限、Tool 或 Workflow。修改既有 `SKILL.md` 会自动改变其内容指纹并使运行快照失效，不应要求修改执行代码。
- `model/`：脱敏投影、模型客户端和模型输出接收；不查询业务数据。
- `contract/`：模型输入、理解结果、绑定结果和严格 JSON 合同；只验证结构与安全边界。
- `tools/`：内部已登记 Tool 合同。当前没有外部 MCP 服务，不能将内部 PHP Handler 伪称为 MCP；将来真实接入 MCP 时，在 `mcp/` 建适配器，不让它直接触达 Reader 或权限。
- `workflows/`：Workflow 图和 Action 声明，只组合 Tool 编号，不读取 Skill 正文，也不实现数据公式。
- `registry/`：把 Skill、Tool、Workflow 和受权限收窄后的指标能力组合成可冻结的运行注册表。
- `execution/`：上下文承接、引导、计划编译、执行、运行状态、导出和监控；不靠中文词表判断用户意图。
- `management/`：后台管理中的显示、启停与受限运行策略；不能覆盖 Skill、指标、权限或 Tool。
- `config/`：模型配置及私有运行存储。
- `semantic/`：服务端对模型输出做的结构性、证据性核验；不是中文问法枚举器。

`AiGatewayServices` 是现有 HTTP 兼容入口。它只应作为稳定门面；新增职责不得继续堆入该文件，后续拆分以应用编排、上下文、结果呈现三个独立服务承接。

## 修改规则

1. 修改 Skill 内容，只改对应 `skills/<skill>/SKILL.md`；内容哈希是运行版本依据，不能用改 Tool、Workflow 或 Reader 来“配合”某一句问法。
2. 新增或调整数据能力，先改统一指标注册表及 Reader，再由 `registry/` 派生可用能力；不得把指标表复制进 Skill、Tool 或前端。
3. 新增内部执行能力，先在 `tools/` 声明合同，再在 `workflows/` 组合；模型永远不拿到 Handler、SQL 或凭证。
4. 新增外部 MCP 时，只能经 `mcp/` 适配器、脱敏投影、权限复核和 Tool 合同进入系统；不能复用浏览器身份或跳过统一 Reader。
5. 所有运行结果、权限和数据范围仍由服务端在执行前复核；Skill、模型和前端不能扩大它们。
