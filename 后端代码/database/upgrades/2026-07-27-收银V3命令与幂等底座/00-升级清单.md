## 二、执行顺序

**先升级数据库，再部署代码。**

V3 命令网关在事务内会先做表就绪检查（`CashierV3CommandGatewayServices::assertTablesReady`）；
表缺失时返回 `COMMAND_TABLE_NOT_READY` 并拒绝执行，不会写坏数据。
但为避免上线窗口内 V3 入口整体不可用，仍按「先库后码」执行。

旧收银台（`/cashierapi/*`）完全不读写这三张表，先执行本包不影响现网业务。

## 六、MySQL 5.6 兼容性

按 008 实测的 **MySQL 5.6.50** 作为最低兼容基线编写。本包不使用：

JSON 类型与函数、生成列、窗口函数、CTE、`CHECK` 约束、`SKIP LOCKED` / `NOWAIT`、
降序索引、`ALGORITHM=INSTANT`、`RENAME INDEX`、`utf8mb4_0900_*` 排序规则。

索引长度自检（严格基线 `< 767`；参与唯一索引的标识列一律 ASCII，1 字符 = 1 字节；
`innodb_large_prefix=0` 时 COMPACT 行格式单索引上限 767 字节）：

| 索引 | 字节数 | 结论 |
|------|--------|------|
| `uk_idempotency_key(varchar(128) ascii)` | 128 | OK |
| `uk_state_context_id(varchar(64) ascii)` | 64 | OK |
| `uk_scope_resource(scope_type16+scope_id32+kind32+id64 ascii)` | 144 | OK |
| `uk_identity(int+int+varchar(128) ascii)` | 136 | OK |

**已在真实 MySQL 5.6.51 容器实测**：镜像 `mysql:5.6.51`（记录 digest），
`innodb_large_prefix=0`，`01`／`02`／`03` 与 `sql/run-sql-matrix.sh` 16 场景矩阵通过。
