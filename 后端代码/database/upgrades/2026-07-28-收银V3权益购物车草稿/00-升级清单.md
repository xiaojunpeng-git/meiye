## 权威边界

- 三张表只保存 A1 的服务端工作台草稿、结构化草稿行和权益资源版本，不是销售、核销、服务、库存、业绩或报表事实。
- 权益业务主表仍是剩余次数、有效期、占用和可用性的权威源；`eb_cashier_v3_entitlement_resource_version` 只提供租户内既有权益资源的乐观并发版本及来源指纹。
- A1 加入购物车不预留、不扣减权益、不写经营事实、不写 Outbox。正式结账／完成服务必须在后续成功事务中重新锁定并复核业务主表。
- `workspace_draft` 不重复保存 `current_version`。工作台并发版本继续由 C1 的 `cashier_workspace` 资源合同统一推进；新草稿的 `customer_mode` 数据库默认值为 `guest`，但已有会员草稿不得在重载时被默认值覆盖。
- 权益行的会员、持卡实例、来源明细、项目、数量、体验标记和两个来源版本均使用明确列；`is_experience` 只保存本行后续业务处理意图，值域固定为 `0`／`1`，本身不是已发生的核销事实。`craftsmen_json` 与 `display_snapshot_json` 只保存草稿人员选择及发生前展示快照，不承担资源身份或可用次数权威性。
- `eb_store_order.cash_pay_price` 与 `yue_pay_price` 属于整单欠款判定输入；它们与其余旧权威读取列在 01／03 中只校验存在，不对历史表绑定整表哈希或显示宽度。

## 变更范围

1. 新建 `eb_cashier_v3_workspace_draft`：一份后端强制门店、操作人和工作台上下文对应一份当前草稿；新建时默认顾客模式为游客。
2. 新建 `eb_cashier_v3_workspace_line`：按 `workspace_id + line_key` 唯一保存 `sale`／`entitlement_service` 结构化草稿行，并以 `is_experience=0/1` 保存该行是否按体验项目进入后续核销。
3. 新建 `eb_cashier_v3_entitlement_resource_version`：按 `resource_kind + resource_id` 唯一保存 tenant 共享权益资源版本、会员归属及来源指纹。

资源种类固定为 `member`、`card_holder`、`member_benefit_pool`，资源 ID 必须是无前导零的正整数文本；权益草稿行的服务对象固定为 `self`／`friend`，体验标记固定为 `0`／`1`。预检和后验会拒绝旧别名、复合伪 ID、未知枚举与非法体验标记。

## 执行顺序

1. 备份并核对目标数据库、真实表前缀和最低 MySQL 版本。
2. 核对 `SHA256SUMS.txt`，确认目标库未使用本升级键。
3. 确认并验证前置升级 `20260727-001-cashier-v3-command-idem`。
4. 核对六张旧权威表均为 InnoDB，必要列、权威主键及 `uid`／`oid`／`cart_info_id`／`order_id` 查询前导索引完整；缺失时先单独评估旧表修复和锁表窗口。
5. 执行 `01-升级前检查.sql`；只允许三张目标表全部不存在，或三张均已精确匹配本合同。
6. 执行 `02-正式升级.sql`，再重复执行一次以验证安全重放。
7. 执行 `03-升级后验证.sql`，必须输出 `VERIFY_OK`；后验会再次检查六张旧权威表，关闭预检后的结构漂移窗口。
8. 完成 A1 权益查询、跨店权限、同工作台并发、旧版本冲突及草稿重放测试。
9. 业务验证通过后，才登记 `eb_database_upgrade_log` 并更新四库执行状态。

## 索引与 MySQL 5.6 说明

- 所有身份／资源键均使用 `ascii_bin`；最长组合唯一键为 `workspace_id(64) + line_key(64) = 128` 字节，低于 COMPACT/Antelope 的 767 字节限制。
- 所有索引必须为完整列索引，`SUB_PART` 必须为空；预检和后验会拒绝前缀索引。
- `source_version`、`detail_version` 和 `current_version` 使用 unsigned bigint 且默认从 `1` 开始。`is_experience` 使用 unsigned tinyint 且默认 `0`。MySQL 5.6 不提供可靠 CHECK，本轮由服务端写入合同和预检／后验数据检查共同拒绝非法值。
- 三张新表不扫描既有业务表，不回填历史权益，不建立外键，也不修改旧核销路径。
- 本包不自动给旧权威表补索引：生产旧表可能较大，缺失时必须使用独立升级键、低峰窗口和真实 `EXPLAIN` 证据处理，不能在本包静默 ALTER。
