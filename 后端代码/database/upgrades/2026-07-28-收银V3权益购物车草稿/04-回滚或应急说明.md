# 回滚或应急说明｜20260728-005-cashier-v3-entitlement-draft

## 首选应急方式

先关闭 `query-checkout-entitlements`、`add-checkout-entitlement-lines` 及对应服务端草稿写入口，保留三张表和诊断数据。MySQL DDL 会自动提交，本升级包不能宣称事务回滚；执行前必须完成目标库备份。

三张表是 A1 草稿／版本投影，不是会员权益、销售、核销、服务、库存或经营事实的权威源。`customer_mode` 的游客默认值只作用于新工作台草稿，`is_experience` 也只是草稿行意图；两者都不能替代成功核销事务产生的权威记录。停用入口后，旧收银与旧核销业务主表不应因本包被改写。

## 尚未启用业务写入

只有同时满足以下条件，才可由 Codex 在已核对的具体目标库上另行生成一次性回滚 SQL：

- 已关闭所有读取和写入三张表的代码入口；
- `eb_cashier_v3_workspace_draft` 为 0 行；
- `eb_cashier_v3_workspace_line` 为 0 行；
- `eb_cashier_v3_entitlement_resource_version` 为 0 行；
- 目标库备份已经验证可恢复；
- 没有任何其他已部署版本依赖这些表。

本说明不提供可直接复制执行的 `DROP`，避免在错误站点或已有草稿／版本数据时误删。

## 已产生草稿或版本数据

禁止直接 DROP、TRUNCATE、把 `current_version` 改小或复用旧版本。应：

1. 停止新权益草稿写入。
2. 保留草稿行、来源版本和来源指纹用于并发问题排查。
3. 修复代码后使用同一工作台版本重新加载权威权益；不得用展示快照反写权益主表。
4. 如需结构变更，创建新的 `upgrade_key`；不得原地改写已在任一目标库执行成功的 SQL。

## 故障处理

- 草稿与权益业务主表不一致：以权益业务主表为权威，废弃或重建草稿，不覆盖业务主表。
- `source_fingerprint` 变化：要求重新查询并携带新正版本，不把旧草稿静默迁移到不同来源。
- 工作台版本冲突：返回冲突并刷新当前服务端草稿，不做最后写入覆盖。
- 权益已被其他门店或旧核销路径消费：最终服务事务必须重新锁定并拒绝旧版本；A1 草稿成功不代表权益已预留。
- 发现 `source_version`、`detail_version` 或 `current_version` 为 0：立即停止相关写入口并调查服务端合同，不得把 0 解释为跳过版本校验。
- 发现 `is_experience` 不为 `0`／`1`：立即停止相关草稿写入口并调查输入校验，不得把未知值默认为体验项目或普通项目。

## 不可执行操作

- 不从 `display_snapshot_json` 或 `craftsmen_json` 推导权限、可用次数或会员归属。
- 不因数据库默认 `customer_mode='guest'` 而覆盖已有会员草稿；默认值只允许在新建草稿时生效。
- 不直接从 `is_experience` 草稿值补写历史核销；只有后续成功业务事务才能固化体验项目事实。
- 不把草稿行转换成零金额销售订单来代替核销／服务。
- 不因停用 A1 而删除或改写已发生的销售、核销、服务、库存、业绩、事件或事实。
- 不执行四库 SQL、部署或远程写入，除非后续固定版本通过双重验收并完成发布门禁。
