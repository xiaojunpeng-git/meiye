# 升级清单｜20260728-003-cashier-v3-event-outbox

## 范围

- 新建统一业务事件、通用 Outbox、追加式租约审计和 consumer-once 四张表。
- 业务事件与领域主表、资源版本和命令回执在同一事务写入。
- 业务事件显式保存 `aggregate_version`；统一 Outbox 显式保存 `organization_path`、`member_id` 和 `operator_id`，下游无需从 payload 猜权限维度。
- `eb_cashier_v3_outbox_attempt` 每次 claim／renew／fail／ack／manual／rejected 都追加一行，不覆盖同一 fencing generation 的旧里程碑。
- 本包不建立经营事实表，不替代现有退款专用 Outbox。
- `member.created` 首批没有真实消费者，只写业务事件，Outbox 行数必须为 0。

## 前置和执行顺序

1. 确认目标库已执行并登记 `20260727-001-cashier-v3-command-idem`，且命令回执、资源版本、工作台上下文三张表通过精确结构合同。
2. 确认 `20260728-003-cashier-v3-event-outbox` 未登记。
3. 执行 `01-升级前检查.sql`。旧会员专用 Outbox 不存在或为空才允许继续；非空立即停止并另立迁移。
4. 执行 `02-正式升级.sql` 两次。
5. 执行 `03-升级后验证.sql`，必须输出 `VERIFY_OK`；该步骤会再次检查 C1 依赖和旧会员专用 Outbox，防止预检后的窗口写入。
6. 本地业务验证通过后登记 `20260728-003-cashier-v3-event-outbox`。
7. 再执行修订后的 `20260728-002-cashier-v3-member-consistency`。

## 兼容与状态

- SQL 按 MySQL 5.6.51 能力编写，不使用 JSON、CTE、窗口函数、CHECK、SKIP LOCKED 或 NOWAIT。
- 唯一索引标识列统一 `ascii_bin`，最大唯一索引长度低于 767 字节。
- Outbox 候选扫描索引固定为 `consumer_code + status + available_at/lease_until + id`，不同消费者不会互相扩大候选扫描。
- `aggregate_version` 为 `bigint unsigned NOT NULL DEFAULT 1`；01／03 同时阻断既有 `aggregate_version=0` 数据。
- 007／008／012／rh：均未执行。不得把本地容器验证写成生产实测。
- 本次未授权远程连接、四库 SQL、部署或 push。

## 状态机

`10 PENDING -> 20 PROCESSING -> 40 SUCCEEDED`；失败进入 `30 RETRY_WAIT`，第 8 次失败进入 `50 MANUAL_FAILED`。租约 60 秒、建议 20 秒续租，每批最多 50。所有 ACK、失败和续租使用 `id + status + owner + lease_token + fencing_generation` 五元组。
