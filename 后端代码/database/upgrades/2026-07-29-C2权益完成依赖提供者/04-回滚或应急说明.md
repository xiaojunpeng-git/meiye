# Rollback and interrupted-DDL recovery

Preferred rollback is to keep the C2 entitlement completion Gateway disabled. These tables are eventless technical metadata and do not make the business action reachable by themselves.

Do not delete a non-empty debt guard, mutation receipt, staff profile version, or occupation version table. They preserve concurrency identities and idempotent version history.

For an interrupted first install:

1. Do not rename, truncate, or drop any target table.
2. Run `05-部分创表恢复.sql`.
3. Only `PARTIAL_DDL_RECOVERY_READY` permits rerunning `02-正式升级.sql`.
4. Run `03-升级后验证.sql` before registering the upgrade.

A destructive rollback SQL may be prepared separately only when the Gateway was never activated, all four tables are empty, the upgrade key is not registered, a verified backup exists, and the product manager separately authorizes that exact rollback.
