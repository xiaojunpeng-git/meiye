# 回滚或应急说明

本升级修改余额权威主表并建立数据库触发器。`balance_version` 一旦被页面或命令上下文使用，就是并发历史的一部分，不能在线重置、回填为时间戳、改成金额哈希或迁移到影子表。

发生异常时：

1. 立即保持 `submit-checkout` 未激活，或先关闭 V3 余额扣款入口。
2. 停止目标库余额写入，保存错误、事务、触发器、会员主行和 `eb_user_money` 证据。
3. 执行 `05-部分升级恢复审计.sql` 判断是可继续的精确部分升级，还是异构结构。
4. 精确部分升级只允许重跑同 SHA 的 `02-正式升级.sql`；异构结构必须人工复核，不自动删列、删索引或覆盖触发器。
5. 余额三字段不一致时，不由迁移静默修值。应按权威来源流水、充值、退款、作废和人工调整记录形成可审计对账与修复方案。

只有在 V3 尚未激活、所有调用者已停止、没有任何已签发 `member_balance` 版本上下文，并经完整备份与审批后，才可考虑删除本升级新增的触发器或列。该破坏性回退不包含在本升级包内。
