# 收银 V3 权益预约读取索引

- 升级键：`20260729-018-cashier-v3-entitlement-reservation-read-index-v1`
- 兼容基线：MySQL 5.6.51 / InnoDB。
- 变更：仅为 `eb_store_reservation_order` 增加 BTREE 读取与锁定索引 `idx_c2_entitlement_cart_info(cart_info_id,id)`（若已有等效索引则不重复创建）。

## 权威边界

本包不迁移、回填、删除或改写任何旧预约、卡项、订单、房间、收款、核销、服务或业绩数据。它只保证 V3 权益读取和事务内占用复核可以按卡内项目明细定位旧预约记录，避免全表扫描和不受控范围锁。

## 执行顺序

1. 仅对被点名的单一实例备份并核对表量、现有索引和可用磁盘。
2. 校验 `SHA256SUMS.txt`。
3. 执行 `01-升级前检查.sql`，仅 `PRECHECK_OK` 可继续。
4. 在低峰执行 `02-正式升级.sql`。MySQL 5.6 DDL 自动提交，异常后先运行 `03` 判断实际索引状态，禁止猜测或手工删除。
5. 执行 `03-升级后验证.sql`，仅 `POSTCHECK_OK` 可登记本升级键。
6. 以 `EXPLAIN` 验证 V3 按 `cart_info_id` 的预约读取走前导索引，再开放权益相关动作。

## 风险与回滚

`ALTER TABLE ... ADD KEY` 可能扫描并短暂锁定旧预约表。本地测试库与任一客户实例的表量不同，四个客户实例必须分别评估和执行。本包不提供直接删除索引命令；应急时优先停用 V3 权益入口或回退代码，保留普通索引。
