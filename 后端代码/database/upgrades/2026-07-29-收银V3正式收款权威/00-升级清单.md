# 收银 V3 正式记账收款权威升级清单

- 升级键：`20260729-012-cashier-v3-payment-collection-authority-v1`
- 合同：`cashier-v3-payment-collection-authority-v1`
- 权威来源：最终结账事务内仍保持加锁的 `ready_for_submit` 结账聚合，以及同一事务已生成并写入的正式销售订单身份。
- 当前范围：只接受 `sale_only`；余额扣款、欠款、纯权益和混合结账在各自权威模块接线完成前必须拒绝，不能静默跳过。
- 方式：仅银联、微信、支付宝、大众验券、抖音验券、合作方收款、其他收款；`old_card_entry` 不是收款事实，必须拒绝。
- 粒度：每个最终 payment draft 固定一条正式 collection；技术 batch 只负责整单唯一、并发串行和 0..7 条明细总额对账，不冒充额外收款事实。
- 金额：所有金额使用整数分；明细合计必须同时等于结账请求的 `selected_payment_amount_cents` 与 `cash_performance_amount_cents`。本阶段 `sale_only` 且余额/欠款均为 0，因此还必须等于 `receivable_amount_cents`。
- 历史：同时保存服务端权威方式代码/名称、支付草稿业务时间、最终成功时间、操作人、门店组织、来源单、外部参考号和备注快照，后续改名不得反改历史。
- 幂等：同租户结账请求只允许一套 batch；同 payment draft 只允许一条 collection；服务端 HMAC ID 与自然键稳定。相同命令和不可变载荷只读重放，任何漂移均拒绝。
- 事务：writer 只能由最终结账 caller-owned transaction 调用，且先锁定并核对已写入的正式销售订单；自身不得开启、提交或回滚事务。
- 状态预留：V1 只写 `settled/forward/version=1`；退款、作废和更正必须以后续冲销合同追加记录，不覆盖原收款。
- 激活边界：本包不修改 Gateway、manifest、CashierModule、前端、旧订单查询、事实/事件/Outbox，也不激活 `submit-checkout`。
- 旧表边界：不读取、不写入、不迁移 legacy 收款或 `store_order`；历史兼容另立任务。

执行顺序：

1. 针对产品经理明确点名的单一客户实例，独立核对 commit、迁移版本、数据库、共享依赖、备份和回滚点。
2. 执行 `01-升级前检查.sql`；仅在输出 `PRECHECK_OK` 后继续。
3. 执行 `02-正式升级.sql`。
4. 执行 `03-升级后验证.sql`；仅 `POSTCHECK_OK` 可登记成功。
5. 多表 DDL 中断时先运行只读 `05-部分创表恢复.sql`；仅输出 `PARTIAL_CREATE_RECOVERY_READY` 才可重跑正式升级。
6. 按 `SHA256SUMS.txt` 校验固定文件，并逐实例登记；一个实例成功不代表其他实例完成。

本升级当前只进入本地统一源码正本，不授权远程执行、部署、历史回填、commit 或 push。未被点名实例保持原状。
