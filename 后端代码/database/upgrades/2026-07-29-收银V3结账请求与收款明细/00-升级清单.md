# Cashier V3 checkout request and settlement drafts

- Upgrade key: `20260729-004-cashier-v3-checkout-settlement`
- Baseline: MySQL 5.6.51 / InnoDB / utf8mb4
- Tables:
  - `eb_cashier_v3_checkout_request`
  - `eb_cashier_v3_checkout_line_draft`
  - `eb_cashier_v3_checkout_payment_draft`

Execution order: backup, `01`, `02`, `03`, then register the real SHA-256 and
fixed code version in `eb_database_upgrade_log`.

The tables are technical preparation state, not business facts. A successful
checkout must later write authoritative business tables, facts and Outbox in
one final transaction. This package does not authorize deployment or database
execution.

Every entitlement-service draft freezes its authoritative card-benefit detail
identity in `entitlement_source_detail_id`. The generic `authority_key` is an
opaque row key and must never be parsed to recover that business identity.
