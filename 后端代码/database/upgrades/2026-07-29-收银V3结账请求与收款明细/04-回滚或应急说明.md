# Checkout settlement migration recovery

Upgrade key: `20260729-004-cashier-v3-checkout-settlement`

This package creates eventless request and draft tables only. It does not
create payment, sale, balance, debt, entitlement, performance or event facts.
Entitlement drafts keep `entitlement_source_detail_id` as an explicit identity;
recovery must not reconstruct it by parsing `authority_key`.

## Partial DDL safe gate

`01-升级前检查.sql` requires all three target tables to be absent. If one,
two or all three already exist while the upgrade key is not registered, the
precheck stops. It never drops a table and never treats a matching name as a
matching schema.

`05-部分创表恢复审计.sql` is a second, non-destructive audit. It reports
target-table metadata and exact row counts. It never repairs or removes an
object; even its review-candidate result still requires an independent,
approved recovery task.

Recovery procedure:

1. Stop application writes and retain a database backup.
2. Record the upgrade-log row, `SHOW CREATE TABLE`, row count and checksums for
   all three target table names.
3. If any target table contains rows, or any structure differs from
   `02-正式升级.sql`, do not drop or replay it. Escalate as an independent
   recovery task.
4. If all three tables exist exactly and `03-升级后验证.sql` passes, register
   the real SQL checksum and fixed code version instead of replaying DDL.
5. Empty partial tables may be removed only in an approved recovery window
   after exact structure verification. This package intentionally provides no
   automatic destructive script.

## Rollback

Before activation these tables contain only eventless drafts. Rollback still
requires a backup and explicit approval. After activation, never drop them as
routine rollback; disable the action and preserve request history for audit.
