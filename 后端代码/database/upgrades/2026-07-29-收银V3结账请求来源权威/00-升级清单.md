# 收银 V3 结账请求来源权威

- `upgrade_key`: `20260729-006-cashier-v3-checkout-source-authority`
- 兼容基线：MySQL 5.6，InnoDB，`utf8mb4_general_ci`
- 依赖：`20260729-004-cashier-v3-checkout-settlement` 已创建三张 eventless 结账草稿表
- 新增：`eb_cashier_v3_checkout_source_reference`
- 数据粒度：一条结账请求绑定的一个服务端已验证来源 `kind + id + source_version + role`
- 允许来源：`service_order`、`hang_order`、`reservation`、`room`
- 写入边界：只能在结账请求创建或 `request_version` CAS `+1` 的同一事务内写入/精确替换
- 版本语义：`source_version` 是来源在准备结账时已由 Gateway 锁定验证的业务版本，后续页面恢复与最终提交必须原样使用
- 不包含：销售、收款、支付尝试、余额、欠款、权益、库存、业绩、事件、Outbox 或经营事实

执行顺序：

1. 运行 `01-升级前检查.sql`，只接受 `PRECHECK_OK`。
2. 运行 `02-正式升级.sql`。
3. 运行 `03-升级后验证.sql`，只接受 `POSTCHECK_OK`。
4. 由发布流程登记本升级键；不得仅凭建表成功视为已上线。

如果正式升级中断，先运行 `05-部分创表恢复.sql`。脚本只审计，不自动删除或改写已存在对象。
