# 收银 V3 销售购物车权威行

- 升级键：`20260729-008-cashier-v3-sale-cart-authority`
- 适用：MySQL 5.6.51
- 顺序：`01-升级前检查.sql` → `02-正式升级.sql` → `03-升级后验证.sql`
- 变更对象：`eb_cashier_v3_workspace_line` 的销售草稿权威字段，以及缺失时补充 `eb_store_card_related(card_product_id,id)`、`eb_store_card_related(product_id,card_product_id,id)` 查询索引；不写订单、支付、库存、业绩或会员卡事实。

新增持久字段：门店商品 ID、SKU ID、商品类型、服务端单价/原价整数分、商品与卡项定义指纹、结构化权威快照。`sale` 行必须完整；既有 `entitlement_service` 行保持默认空值，原草稿指纹口径不变。

`02` 的每条 DDL 均按 `information_schema` 判断后执行，可从 MySQL DDL 部分成功状态继续。任何同名异构列或索引由 `01` 阻断。

## 销售目录并发合同

- 全局顺序固定为 `catalog_card_definition(41)`、`catalog_product(42)`、`catalog_sku(43)`、库存资源 `46/47/50/55/56`，最后才是 `cashier_workspace(150)`。
- `catalog_card_definition` 使用对应 `eb_store_product.id` 主行作为精确串行点；锁定父行后只读并复核 `eb_store_card_related` 全量定义，不对关系表做范围锁。
- 商品与 SKU 只允许按精确主键逐行锁；同 kind 的规范正十进制 ID 复用全局资源 comparator 按数值顺序，例如 `2` 先于 `10`。
- 所有新增、删除、停用或改写 `eb_store_card_related` 的兼容写路径，都必须在同一事务中先锁对应卡商品主行。旧写入口完成共锁审计和永久并发回归前，销售目录 readiness 必须 fail-closed，不得激活添加或结账路径。
- 所有新增 SKU 或改写 `product_id/unique` 身份的兼容写路径，都必须在同一事务中先锁所属商品主行；否则无锁发现后可能出现未纳入计划的同 identity 幻影。该写路径共锁审计未完成时同样保持 fail-closed。
- 组件反向发现固定使用以 `product_id` 开头的索引；锁后若发现新卡父商品，整笔回滚并按 41→42→43 重新规划，禁止在商品锁后补拿卡锁。
- SKU 购买后有效天数的权威列是 `eb_store_product_attr_value.write_days`；不得读取仅属于旧接口展示别名的 `days`。
- `eb_store_product_attr_value.unique` 在真实旧库不是唯一约束；同一商品出现多个相同 unique 的 SKU 时必须阻断卡组成解析，禁止覆盖映射后任选一行。静态重复检查不能代替上述写路径共锁。
