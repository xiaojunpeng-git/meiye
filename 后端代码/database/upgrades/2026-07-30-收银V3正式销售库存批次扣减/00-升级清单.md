# 收银 V3 正式销售库存批次扣减

- 升级键：`20260730-002-cashier-v3-sale-inventory-settlement-v1`
- 兼容基线：MySQL 5.6.51 / InnoDB / `utf8mb4_general_ci`。
- 依赖：`20260730-001-cashier-v3-sale-sku-freeze-v1`、正式销售订单、收款、统一事件与 Outbox、库存批次事实，以及 `20260729-003-inventory-batch-query-facts` 已完成。
- 变更：新增 V3 普通库存产品销售的不可变回执表 `eb_cashier_v3_sale_inventory_receipt`。批次实际扣减继续写入既有 `eb_inventory_stock`、`eb_inventory_batch` 和 `eb_inventory_batch_movement_fact`。

## 权威边界

一条回执对应一个成功的 V3 `sale_only` 结账请求中的库存销售部分；一条批次流水对应“一个正式销售订单明细在一个真实批次上的一次扣减”。库存销售不是项目服务耗材，不写入项目配方、服务核销、缺口或 `inventory_consumption_receipt`。

本包不回填、不迁移、不删除或兼容旧商品库存、旧订单、旧房间、旧预约或历史挂单。未建立批次库存映射的商品会由新服务端路径 fail-closed，不能以旧库存字段代替真实批次库存。

## 执行顺序

1. 仅对被产品经理明确点名的单一实例，核对当前 commit、数据库、迁移记录、共享进程、备份和回滚点。
2. 校验 `SHA256SUMS.txt`，执行 `01-升级前检查.sql`；仅 `PRECHECK_OK` 可继续。
3. 执行 `02-正式升级.sql`，再执行 `03-升级后验证.sql`；仅 `POSTCHECK_OK` 可登记升级键。
4. 先验证库存普通产品的成功结账、库存不足全回滚和同键重放；不测试旧数据迁移。

本包仅是源码正本中的本地迁移，不授权远程写库、部署、提交或 push。
