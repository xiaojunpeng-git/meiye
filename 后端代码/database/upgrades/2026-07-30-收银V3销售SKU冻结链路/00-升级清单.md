# 收银 V3 正式销售 SKU 冻结链路

- 升级键：`20260730-001-cashier-v3-sale-sku-freeze-v1`
- 兼容基线：MySQL 5.6.51 / InnoDB / `utf8mb4_general_ci`。
- 依赖：收银 V3 结账草稿与正式销售订单权威迁移已完成。

## 变更

为 `eb_cashier_v3_checkout_line_draft` 与 `eb_cashier_v3_sales_order_line`
分别增加 `catalog_sku_id`。它是新 V3 普通商品结账时冻结的 SKU 权威 ID，和
`item_id`、`item_code_snapshot` 一起保存；库存扣减只能按该 ID 锁定 SKU，再交叉
核对商品 ID 与 SKU 文本快照，不能用文本猜测 SKU。

旧草稿和旧订单不回填。历史行可保持 `0`；新的普通商品 `sale_only` 正式结账缺少
冻结 SKU ID 时由服务端 fail-closed，不会写销售、收款、库存或事实。

## 执行顺序

1. 仅对产品经理明确点名的单一实例核对当前 commit、迁移记录、备份与回滚点。
2. 校验 `SHA256SUMS.txt`，运行 `01-升级前检查.sql`，仅 `PRECHECK_OK` 可继续。
3. 运行 `02-正式升级.sql`，再运行 `03-升级后验证.sql`，仅 `POSTCHECK_OK` 可登记。
4. 再升级依赖本包的正式销售库存批次扣减包，并验证一次新商品的完整结账。

本包不授权远程写库、部署、旧数据回填、提交或 push。
