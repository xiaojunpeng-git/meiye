# 库存 V3 跨主体调拨在途收货

- Upgrade key: `20260802-003-inventory-v3-cross-subject-transfer-receipt`
- Dependency: 已具备 `eb_inventory_location`、`eb_inventory_stock`、`eb_inventory_batch`、`eb_inventory_batch_movement_fact`、请货单／行和组织根结构；`01-升级前检查.sql` 会对这些实际依赖及升级登记状态 fail-closed 检查。
- Authority: 请货单新增供货主体快照；新建跨主体调拨单据、商品行、FEFO 批次分配和请货履约关联。商品行描述用户请求的总量，批次分配行记录发货后实际批次与谱系，不修改旧库存或同门店多仓调拨表。
- State: `DRAFT -> DISPATCHED -> RECEIVED`，取消只允许在发货前；发货仅写调出事实，收货才写调入事实。
- Reconciliation: 每条已发货批次分配必须有一条调出事实；已收货批次分配还必须有一条调入事实，数量和成本金额成对守恒；在途单不得有调入事实。关联请货仅在收货后写履约记录并更新为部分完成或已完成。
- Execution: 先核对 `SHA256SUMS.txt`，再按 `01-升级前检查.sql` -> `02-正式升级.sql` -> `03-升级后验证.sql` 执行；只有 `PRECHECK_OK` 与 `VERIFY_OK` 都通过，发布流程才可按实际 `02-正式升级.sql` SHA、代码版本和执行人登记 `eb_database_upgrade_log`。登记失败或任一步失败都不得把本升级视为完成。
- Rollback: 已发货或已收货单据不得删除、作废或取消。需要退回时由当前持货方另建一张反向调拨，保留原事实和谱系。
