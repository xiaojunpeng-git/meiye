# 收银 V3 结账草稿服务标签快照

- 升级键：`20260803-004-cashier-v3-checkout-draft-service-tags-v1`
- 兼容基线：MySQL 5.6 / InnoDB / `utf8mb4_general_ci`。
- 依赖：`20260802-001-cashier-v3-sales-order-service-tags-v1` 已执行。

## 变更

为 `eb_cashier_v3_checkout_line_draft` 新增 `service_object` 与
`is_experience` 两个结账草稿快照列。项目行在创建结账请求时保存已锁定的
本人／朋友和体验标记；产品与卡项保持空对象、非体验。

本包不回填、更新或删除既有草稿、订单或事实。既有行使用列默认值（空对象、
非体验），因此失败重试仍由原结账请求、版本和幂等键控制。

## 执行顺序

1. 对点名的本地恢复测试库执行 `01-升级前检查.sql`，仅 `PRECHECK_OK` 可继续。
2. 执行 `02-正式升级.sql`，再执行 `03-升级后验证.sql`，仅 `POSTCHECK_OK` 可登记。
3. 核对 `SHA256SUMS.txt` 后写入完整 `eb_database_upgrade_log` 记录，并重跑 `03`。
4. 仅在 `ruihao_test_recovered_20260801` 验证一笔新结账或原失败请求的受控重试。

本包不授权远程写库、生产部署、历史回填、提交或 push。
