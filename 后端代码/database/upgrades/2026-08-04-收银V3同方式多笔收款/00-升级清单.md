# 收银 V3 同方式多笔收款

- `upgrade_key`: `20260804-001-cashier-v3-repeat-payment-method-drafts`
- 兼容基线：MySQL 5.6 / InnoDB / `utf8mb4_general_ci`。
- 前置：`20260729-004-cashier-v3-checkout-settlement` 已登记，且
  `eb_cashier_v3_checkout_payment_draft` 存在。

## 变更

删除 `eb_cashier_v3_checkout_payment_draft` 上错误的唯一索引
`uk_request_method (request_id,payment_method)`。同一结账请求现在可保留多条
相同记账收款方式的独立草稿行。

本包保留以下不可变边界：

- `uk_payment_draft_id` 继续保证草稿行 ID 唯一。
- `uk_request_payment_authority (request_id,payment_authority_key)` 继续保证
  每条收款权威键唯一。
- 最终结账仍校验每条金额为正整数、总收款加余额加欠款恰好等于应收，并按每条
  草稿行生成独立 `payment_collected` 事实。

不回填、不截断、不更新和不删除任何既有数据。

## 执行顺序

1. 在被明确点名的实例执行 `01-升级前检查.sql`，仅 `PRECHECK_OK` 可继续。
2. 执行 `02-正式升级.sql`，再执行 `03-升级后验证.sql`，仅 `POSTCHECK_OK` 可登记。
3. 核对 `SHA256SUMS.txt` 后登记完整 `eb_database_upgrade_log` 记录。
4. 受控验收须覆盖：微信加支付宝、两笔支付宝、余额加微信加支付宝；每笔最终
   收款必须产生独立事实且合计与应收一致。

本包不授权本地恢复库执行、远程写库、生产部署、提交或 push。
