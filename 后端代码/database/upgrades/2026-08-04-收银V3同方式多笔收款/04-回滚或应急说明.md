# 同方式多笔收款索引变更的应急说明

本包只删除 `uk_request_method (request_id,payment_method)`，不修改任何业务行。

如升级中断且 `03-升级后验证.sql` 未通过，停止该实例后续结账验收，先只读确认
当前索引状态和升级登记状态。不得通过删改草稿行恢复。

如确需恢复旧限制，必须先确认每个 `request_id + payment_method` 组合没有多条草稿
记录；否则重新加回唯一索引会失败并破坏已确认的多笔收款能力。满足条件后，在独立
处置任务中执行：

```sql
ALTER TABLE `eb_cashier_v3_checkout_payment_draft`
  ADD UNIQUE KEY `uk_request_method` (`request_id`,`payment_method`);
```

恢复旧索引会再次禁止同一方式多笔收款，不能作为正常发布后的常规操作。
