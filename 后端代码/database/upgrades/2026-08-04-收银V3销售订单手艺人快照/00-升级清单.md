# 收银 V3 销售订单手艺人不可变快照

- `upgrade_key`: `20260804-002-cashier-v3-sales-order-craftsmen-snapshot-v1`
- 兼容基线：MySQL 5.6 / InnoDB / `utf8mb4_general_ci`。
- 前置：`20260803-004-cashier-v3-checkout-draft-service-tags-v1` 已登记，
  `eb_cashier_v3_checkout_line_draft` 与 `eb_cashier_v3_sales_order_line` 已存在。

## 变更

为结账草稿行和正式销售订单行各新增 `craftsmen_snapshot_json`。新结账会将
服务端锁定的项目手艺人 ID、员工 ID、名称、主手艺人、顺序与劳动权重写入草稿，
随后随销售订单行不可变保存。订单详情只读取该快照，绝不按会员、项目或当前员工
资料反查，从而避免人员改名、改岗或同会员重复服务时串单。

MySQL 5.6 不允许 `TEXT/MEDIUMTEXT` 指定默认值。本包使用
`MEDIUMTEXT NOT NULL`；新代码对所有新草稿显式写入 `[]`，历史空文本读取为
空数组。此兼容处理不更新、回填或删除任何旧行。

项目行快照必须是受服务端校验的数组；产品、卡项和权益服务草稿固定为 `[]`。
快照纳入结账行指纹和销售订单不可变指纹，重试只能得到同一内容。

## 执行顺序

1. 在被明确点名的实例执行 `01-升级前检查.sql`，仅 `PRECHECK_OK` 可继续。
2. 执行 `02-正式升级.sql`，再执行 `03-升级后验证.sql`，仅 `POSTCHECK_OK` 可登记。
3. 核对 `SHA256SUMS.txt` 后登记完整 `eb_database_upgrade_log` 记录并重跑 `03`。
4. 受控验收新建一笔已选择手艺人的项目销售，确认结账草稿、销售订单详情与重放
   均显示发生时人员快照；旧订单显示空人员，不能伪造当前人员。
