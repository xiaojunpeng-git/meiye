# 门店房间名称乱码修复

- `upgrade_key`: `20260805-009-store-room-name-encoding-repair`
- 兼容基线：MySQL 5.6 / InnoDB / `utf8mb4`。
- 目标实例：仅经受控发布流程明确点名的实例；本地恢复测试库的已核实目标为 `store_id=118`。

## 范围和审计边界

本包只修复已核实的两条 QA 房间资料：`eb_table_qrcode.id IN (9,10)`，且每条均以
`store_id`、排序号、原始 `HEX(remarks)` 三重条件锁定。不会扫描或猜测性转换其他房间
名称，也不会创建第二套房间资料源。

执行输出中的升级前、升级后行和 `eb_database_upgrade_log` 登记共同构成审计证据，必须
随该实例发布记录保存。若任意前检条件不符，停止执行，不得手工改名或扩大 `UPDATE` 条件。

## 执行顺序

1. 对被明确点名的实例执行 `01-升级前检查.sql`；仅 `PRECHECK_OK` 可以继续。
2. 执行 `02-正式升级.sql`，确认受影响行数为 2。
3. 执行 `03-升级后验证.sql`；仅 `POSTCHECK_OK` 可以登记。
4. 核对 `SHA256SUMS.txt`，以实际 SQL SHA、固定源码 commit、实例、执行人与前后结果
   登记 `eb_database_upgrade_log`。

本包不授权本地恢复库执行、远程写库、部署、提交或 push。
