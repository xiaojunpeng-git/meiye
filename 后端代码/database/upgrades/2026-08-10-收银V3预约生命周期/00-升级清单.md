# 收银 V3 预约生命周期

- `upgrade_key`: `20260810-003-cashier-v3-reservation-lifecycle-v1`
- 兼容基线：MySQL 5.6 / InnoDB / `utf8mb4_general_ci`。
- 前置：`20260730-001-cashier-v3-reservation-authority`、
  `20260729-005-c3-service-order-authority` 和
  `20260729-006-c3-generic-service-order-line` 已在目标实例登记。

## 变更

为 `eb_cashier_v3_reservation_line` 新增 `sku_id`。预约编辑以项目 SKU
作为原始规格快照重新校验服务时长，避免同一项目存在多规格时错误按项目 ID
推断规格。

- 新建预约写入 `UNSTARTED`；历史 `PENDING_CONFIRMATION`、`CONFIRMED`
  及其他旧预约保持原状，不回填、不映射、不在本期新生命周期页面开放操作。
- 开始、结束服务由预约主表和服务单在同一业务事务内推进；房间占用和释放仍由
  房间权威锁保护。
- 本升级只增加带默认值的列，不回填、不删除、不覆盖既有预约、服务单、会员或
  销售数据。

## 执行顺序

1. 仅在产品经理点名的独立实例，先只读执行 `01-升级前检查.sql`。
2. 仅预检结果可继续时，执行 `02-正式升级.sql`。
3. 只读执行 `03-升级后验证.sql`，确认 `sku_id_column_count=1` 和
   `APPLY_OK`。
4. 核对 `SHA256SUMS.txt`，登记升级键、实例、执行人、执行时间和验证输出。

本包不授权远程写库、部署、提交或 push。
