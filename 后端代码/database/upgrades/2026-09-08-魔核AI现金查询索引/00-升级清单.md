# 魔核 AI 现金查询来源守卫索引

本迁移仅新增普通非唯一索引，不修改金额、经营状态、权限或历史事实。不改写任何已执行迁移。

## 目标与前提

- 解决充值补收现金查询按租户、来源种类、补收单号检查成功作废时的逐行大范围扫描。
- 正本：本目录 `02-正式升级.sql`；目标表 `eb_cashier_v3_order_center_void_operation`。
- 适用 MySQL 5.7；本地隔离 MySQL 5.7.44 验证不代表生产实例已验收。
- 新索引 `idx_ai_cash_source_guard(tenant_id,source_kind,source_id,status)`，不替代现有索引。
- 仅获得本地研发授权，尚未执行客户实例或本机业务数据库。发布前须逐实例确认备份、代码版本、表结构、索引空间、元数据锁与 DDL 窗口，满足 `XJPMD/17`。
- `ALGORITHM=INPLACE, LOCK=NONE` 不能消除元数据锁等待；不允许失败后自行切换锁表算法。DDL 失败应保持 Excel/AI 相应启用门禁关闭，查明原因。

## 顺序

1. 执行 `01-升级前检查.sql`，表与四列存在且类型与原表合同一致，已有同名索引必须精确一致；发现不同定义停止。
2. 在已授权窗口执行 `02-正式升级.sql`，索引存在时安全重放；不需要停普通查询，但实际 DDL 影响须按实例验证。
3. 执行 `03-升级后验证.sql`，记录索引定义与 EXPLAIN，并按真实实例数据验证查询耗时和取消。
4. 登记迁移、执行人、目标与结果后，才可按已授权流程启用。脚本不授予部署或启用权限。

## 回退

索引不影响业务结果，优先保留索引并回退业务代码。若确需删除新索引，另行批准 DDL 窗口并核对无其他查询依赖；不得删除整个表、回填金额或清理经营事实。不得把删除索引作为自动故障恢复动作。
