# MOHE-AI-00002 运行状态迁移

本目录仅为源代码迁移交付，不表示已执行、验收或发布。当前任务不连接远程数据库。

## 数据架构

- 四张表只保存运行状态、请求指纹、能力版本引用、物理槽位及外发尝试的数字用量；不保存用户问题、20 轮历史、模型 Prompt 或聊天答案正文。
- `eb_mohe_ai_mutex` 的实例行使用 InnoDB `FOR UPDATE`，保护接纳、幂等回执、同人同端活动名额、同会话代际及容量预占的一次事务提交。
- 不改变经营主表、成功事件、事实粒度、指标口径或报表数据权限。可信身份与实例由服务层提供，不能由模型或客户端指定。
- 新接纳只使用立即可用容量，不建立无界等待队列。拒绝保留不含正文的 24 小时幂等回执。
- 逻辑取消、失败、完成都不代表执行线程已停止；已领取的槽位仅由结束全部本地操作的同一 Worker token 释放。租约或 deadline 不释放槽位。
- 到期清理覆盖所有 Run/Receipt/Attempt，不仅成功项。对到期仍持槽的失联执行，先转为无账号、Run ID 或时间明细的实例安全隔离槽，再删除原记录；此值是容量阻断状态，不是长期匿名事件日志。禁止未经监督证明直接清零隔离槽。

## 发布前提

1. 核对目标实例、数据库前缀、最低 MySQL 版本、备份和回滚点。SQL 固定 `eb_`；非该前缀必须由受控发布流程替换，不能投向错误数据库。
2. 验证四表不存在或与完整结构一致。`IF NOT EXISTS` 只允许重复执行，不代替结构验收；发现残缺结构必须停止，不盲目启用。
3. 所有表必须是 InnoDB。运行适配使用专用、没有外层事务的 PDO 连接；事务中只做短元数据操作，不调用模型或经营查询。
4. 部署独立控制容量与截止/清理监督，并实测查询/模型停止后回收执行槽的时延。当前离线 SQLite 测试不证明 MySQL、Swoole 或真实外发停止能力。
5. 新能力保持关闭直到本实例迁移、权限、并发、24 小时清理、取消和端到端验证通过；普通报表导出表改造仍遵循其独立来源/消费者发布屏障。

## 运行接口

`AiRunStore::cleanup()` 应由本实例独立维护任务周期调用；主动读取在到期时立即拒绝，物理清理由维护任务完成。此迁移不自动安装计划任务。

四张表无业务写路径回滚依赖。回滚应用时先关闭 AI 创建、终止并确认执行进程全部停止，按实例清理临时数据；不要在仍有 AI Worker 时直接删表或移除运行守卫。
