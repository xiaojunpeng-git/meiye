# 回滚或应急说明

本升级不删除任何原菜单、角色规则或业务记录。发生前端路由、查询接口或权限异常时，先停止在平台端展示新订单中心菜单，再恢复原菜单可见性。

```sql
SET NAMES utf8mb4;

UPDATE eb_system_menus legacy
JOIN eb_system_menus p ON p.id=legacy.pid
SET legacy.is_show=1
WHERE p.unique_auth='admin-store-order'
  AND p.menu_name='门店订单'
  AND p.type=1 AND p.is_del=0
  AND legacy.unique_auth IN ('admin-store-store_order','admin-store-refund-order','admin-store-writeoff')
  AND legacy.is_del=0;

UPDATE eb_system_menus
SET is_show=0
WHERE unique_auth IN (
  'admin-store-order-center-sales',
  'admin-store-order-center-recharge',
  'admin-store-order-center-refund',
  'admin-store-order-center-debt',
  'admin-store-order-center-service',
  'admin-store-order-center-supplement',
  'admin-store-order-center-gift',
  'admin-store-order-center-card-operation'
) AND is_del=0;
```

不要删除八个菜单记录，也不要从角色 `rules` 中移除 ID：这样可保留幂等升级及下次恢复展示的能力。旧 `/admin/store/order/index`、`/admin/store/refund/order` 和 `/admin/store/writeoff/index` 路由在升级前后均保持不变。

执行回滚 SQL 后同样必须清除平台 `system_menus` Redis 标签缓存，并让管理员刷新菜单／重新登录；否则浏览器和服务端的旧权限快照会继续显示迁移前的菜单树。
