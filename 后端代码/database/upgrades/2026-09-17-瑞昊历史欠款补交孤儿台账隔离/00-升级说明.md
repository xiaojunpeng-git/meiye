# 瑞昊历史欠款补交孤儿台账隔离

## 问题与边界

本包处理的是**不能证明为实际收款**的旧 `store_debt_repay` 台账，不是收款事实回填。
它们的 `repay_order_id` 指向不存在的补交订单，而对应欠款和原订单均仍显示未还；把这类
记录回填为收款，会凭空增加现金业绩。

当前本机预检发现 8 条、13,120 元，分属 3 笔历史卡项欠款。全部补交订单已不存在，
其中可查到的状态记录显示创建后立即撤销；欠款 `repaid_debt` 均为 0。因此它们只能
作为孤儿台账隔离，不能计为收款。

本包严格限定为同时满足以下条件的整笔欠款分组：

1. 欠款仍处于待还，`repaid_debt=0` 且总欠款为正；
2. 该欠款没有成功的 V3 补交；
3. 分组内每一条旧补交都有非零 `repay_order_id`，且该订单已经不存在；
4. 旧补交合计为正，因而与当前已还金额存在明确冲突。

任一条件不成立，一律阻断，不能删除、不能改欠款状态，也不能把它转换为业绩事实。

## 执行与可恢复性

默认仅预检：

```bash
php 01-执行.php
```

执行时先将原始台账和欠款快照写入 `eb_mig_historical_debt_repay_orphan_backup`，再删除
该批确认的孤儿行；不会改动欠款、原订单、会员、V3 收款事实、销售事实或报表。
备份表以 `repay_id` 为主键，保留删除原因和批次时间，可用于逐条恢复。

对 `ruihao` 的实际执行必须得到单独的数据修复授权：

```bash
MOHE_REPAIR_ENV_PATH=/www/wwwroot/rh.cc3798.com/.env \
php 01-执行.php --execute --allow-ruihao
```

执行后运行 `02-执行后验证.sql`，然后重新运行“历史欠款补交收款事实回填”的只读预检。
预期结果是本包隔离的行不再出现在收款回填阻断清单中；本包本身不会补入任何业绩。
