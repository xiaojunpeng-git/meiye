# 瑞昊历史欠款补交收款事实回填

## 要解决的覆盖缺口

`store_debt_repay` 是旧版欠款补交台账。收银 V3 上线前已经成功的补交，
不会自动产生 `cashier_v3_payment_fact`，因此不会进入统一的现金业绩、趋势、
明细、会员排行和收银员排行。新收银 V3 补交已在成功事务中写事实，本包只处理
旧台账中能够完整核验的历史记录。

回填的事实是 `payment_collected / debt_repayment`，记账日期为原补交时间；它只
进入现金业绩。没有冻结原销售行的历史记录不生成销售事实、商品/项目分类或销售
业绩分摊，避免把收款错误归为销售额或某个商品。

## 严格准入规则

每个旧补交仅在以下条件全部成立时才可写入：

1. `store_debt_repay`、欠款、会员和补交门店关系完整，金额和时间有效；
2. 同一欠款的旧补交总额加上已存在的 V3 补交总额，精确等于当前
   `store_debt.repaid_debt`；任何不相等都表示旧台账与欠款状态冲突；
3. 支付方式有可审计的旧代码映射。当前只接受旧 `cash`（旧系统的“记账收款”），
   映射为 V3 `other_collection`，不是纸币现金；其他旧代码进入阻断清单；
4. 同一来源尚未有回填事实，且不存在“事件已写、事实缺失”的半完成状态。

不满足任何一项都只输出原因和样本，不写入。尤其不能根据欠款总额猜测已收金额、
支付方式、操作人、商品分类或原销售明细。

## 一致性与可追溯性

- 每条来源以 `store_debt_repay.id` 生成稳定的事件键、事实 ID、自然键和幂等键；
  重复执行不会重复计入。
- 事实与历史补录事件在同一事务写入；历史补录事件不投递业务 outbox，避免今天
  重放旧日的会员、库存或业绩副作用。
- 原补交时间保存在 `occurred_at`、`settled_at` 和 `business_date`；
  `recorded_at` 仅记录本次回填时间。
- 旧台账没有可靠的历史组织和操作人快照时，明确记录“历史未留存”，不使用当前
  人员冒充原操作人；门店、会员显示名为回填时可解析的快照。
- 首次执行前和执行后均输出金额、来源数、阻断原因及事实数。回滚只删除本包具有
  `historical_debt_repayment:payment:` 自然键的事实和对应补录事件，必须先人工核对。

## 执行方式

默认只读预检：

```bash
php 01-执行.php
```

对 `xinruihao` 写入：

```bash
php 01-执行.php --execute
```

对真实 `ruihao` 写入必须另有明确部署授权，并显式指定：

```bash
MOHE_REPAIR_ENV_PATH=/www/wwwroot/rh.cc3798.com/.env \
php 01-执行.php --execute --allow-ruihao
```

本次本机预检发现的旧 `cash` 台账与欠款的 `repaid_debt` 不一致，会被阻断而不会
被计入报表；先修复来源台账或明确其作废/有效状态，再重新预检。
