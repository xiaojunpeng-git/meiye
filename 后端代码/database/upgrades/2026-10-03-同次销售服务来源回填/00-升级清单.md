# 同次销售服务来源回填

- 升级键：`20261003-001-same-checkout-service-source-backfill`。
- 依赖：先执行 `20261002-001-reservation-market-source-snapshot`，确保服务事实已有六个来源快照列。
- 范围：只修正来源全空、且同租户、同门店、同会员、同结账请求唯一关联到已结算正向销售订单的历史服务事实。预约直接结束服务、纯权益结账及无法确定同次销售来源的记录保持原样；不使用原购卡销售来源。
- 来源：复制销售订单已冻结的一级、二级 ID、名称和展示名称。销售订单没有归因类型快照，服务事实的该列维持原值 `other`，不得查当前来源配置猜测历史类型。
- 执行：先对指定实例独立备份并核对数据库与代码版本，再用 `02-执行.php` 无参数只读预览；核对候选数后以 `--execute` 执行。正式瑞昊库还需 `--allow-ruihao`。完成后运行 `03-升级后验证.sql`，重复执行应新增 0 行。
- 审计：逐条保存服务事实与同次销售订单 ID、修正后的快照、原事实指纹和执行时间；只补空列，不修改业务日期、金额、次数、状态或原指纹。脚本按批事务执行，失败可重跑。
- 回滚：仅在独立备份和审计表仍完整、服务事实来源仍等于本次修正值时，按审计表逐条恢复原空值并标记回滚；其他后续新事实不受影响。数据库升级日志和审计记录保留，不删除来源列。
- 前端源码：无。后端源码：同次销售服务事实写入两处。数据库迁移：本目录。自动化测试：同次销售来源回填集成测试。工程脚本：无。生成物：无。
