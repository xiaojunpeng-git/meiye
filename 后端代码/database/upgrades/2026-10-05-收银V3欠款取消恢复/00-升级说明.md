# R14 欠款取消与恢复

- 范围：一套标准源码，多实例逐个执行；此处只在本地 `ruihao` 开发库执行，未触碰线上实例。
- 依赖：先有 2026-10-02 独立取消欠款表和事件表。MySQL 5.7 / InnoDB。
- 执行前：核对目标实例、代码版本、表前缀与备份；确认 `uq_debt` 仍存在且恢复表不存在。01 脚本不是重复执行脚本，不能再次运行。
- 01 将取消表 `uq_debt` 改为 `idx_debt_latest`，保留全部旧取消事实；新增不可变恢复事实表，一次取消最多一次恢复。新代码必须在迁移完成后发布。
- 权威：`store_debt.status=3` 为当前取消，状态 0 为恢复后的待还；最新取消事实及对应恢复事实用于校验。恢复不改已还金额、原订单或原始卡次数，不生成收款/业绩；可用次数由既有欠款限制公式按当前状态重算。
- 并发：取消、恢复、补交共用债务行锁。命令幂等键和事件版本保护同秒反复操作；取消、恢复、再次取消只追加事实。
- 本地验证：迁移后执行 `tests/cashier-v3/php/r14-debt-cancel-restore-mysql.php` 和 `tests/cashier-v3/php/r14-shared-card-debt-limit-mysql.php`；真实共享卡验证待还、取消、恢复均保留整卡核销上限，全部业务写入由测试外层事务回滚。再执行 03 查询检查。
- 回退：如已有恢复/再次取消事实，不能删除表或恢复 `uq_debt`，否则会破坏历史。只能回退前端入口、保留服务端当前状态及事件读取，制定逐实例兼容回滚方案。
