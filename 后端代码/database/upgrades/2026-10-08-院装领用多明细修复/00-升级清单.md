# 院装领用多明细修复

- 目标：允许一张领用单包含多个商品，或同一商品从多个批次扣减；保留旧退回明细的来源唯一约束。
- 正本：`01-正式升级.sql`。只在已获授权的目标实例备份、预检后执行，不修改 2026-07-30 已执行的建表文件。
- 权威数据：`eb_inventory_salon_usage_document` 和 `eb_inventory_salon_usage_line`。领用行没有来源明细，使用 `NULL`；退回行继续保存被退回的领用明细 ID。
- 升级顺序：先将 `source_usage_line_id` 改为可空，再把所有历史 `ISSUE` 行的 `0` 更新为 `NULL`。唯一键 `uk_document_source_line` 不删除，重复执行升级不再改变已转换记录。
- 验证：运行 `02-升级后验证.sql`；在隔离库执行多商品、多批次、重试、作废与失败回滚测试。业务失败产生的自增 ID 空洞不是单据，不做人工补号。
- 回滚：发布前独立备份表结构与数据；若新版本已有一单多行领用，不能直接改回 `NOT NULL DEFAULT 0`，否则会再次违反唯一键。先回退写入代码、停止新领用，再按事实对账制定前向修复；不能删除有效单据或库存事实。
