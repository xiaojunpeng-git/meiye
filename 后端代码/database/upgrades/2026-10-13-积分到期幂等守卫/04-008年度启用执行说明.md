# 008 年度积分到期启用

本步骤只针对 `008.cc3798.com` 的 `mohe_008:3307` 和 Redis `SELECT 0`。旧 `morestore` 虽配置年度到期，定时器实际上关闭且没有历史清零流水；008 按产品经理 2026-10-13 的新口径真正开启年度自动到期。2026 年 12 月 31 日对 2025 年积分的旧估算约 544 人、88,972 分只是迁移前参考，须以合并目标 UID 后的新试算为准。

## 依赖与只读预检

1. 先部署同一固定版本的 `UserIntegralServices.php`、`UserIntegralJob.php`、幂等表升级及本启用脚本；重载 008 的 PHP 常驻进程和队列工作进程。核对站点、数据库、Redis DB 0、代码 commit、迁移标记及回退版本。不得把此脚本用于其他客户实例。
2. 会员批次 `008-morestore-member-points-r1`、现有积分和保留原 `add_time` 的积分流水必须完成导入并逐项对账。旧账不得经 `UserBill` 模型重写时间。批次表的 `source_sha256`、`target_members`、`current_integral`、`integral_bills` 是启用前固定校验值。
3. 008 站点执行只读检查：`cd /www/wwwroot/008.cc3798.com && php scripts/import/customer_008_integral_expiry_enable.php check`。须返回 `mode=ready` 且 `blockers=[]`；核对重新计算的 `forecast_2026_12_31` 并留存逐会员对账结果。当前代码还会核实目标 MySQL 为 3307、Redis 为 DB 0、配置原值为空、定时器原本不存在、幂等表为空。现阶段会员导入及守卫表未落库时返回 `blocked` 是正确行为。
4. `check` 读取 008 的数据库和 Redis 定时器缓存，不改变业务数据。原站和共机其他实例均不在本步骤的连接范围。

## 固定版本启用与后验

在产品经理确认这一固定版本及 008 写入边界、项目部署门禁满足后，记录实际脚本 SHA-256、会员批次来源 SHA-256 和已部署的本地 commit SHA，再执行：

```sh
cd /www/wwwroot/008.cc3798.com
sha256sum scripts/import/customer_008_integral_expiry_enable.php
php scripts/import/customer_008_integral_expiry_enable.php apply <脚本SHA-256> <会员来源SHA-256> <commit SHA-1>
php scripts/import/customer_008_integral_expiry_enable.php verify
```

`apply` 在单事务中把 `integral_effective_status=1`、`integral_effective_time=3`，新增 `auto_clear_integral` 的 `type=8, cycle=12/31/23/59, is_open=1`，并记启用标记；提交后仅刷新 008 Redis DB 0 的配置和定时器缓存。重复执行只修复提交后缓存刷新失败；启用标记绑定脚本、commit、会员来源及定时器 ID，若任何一项漂移则阻断。`verify` 检查数据库配置、定时器及其缓存。另从 008 应用运行时读取 `sys_config` 两值，均应分别为 `1`、`3`；若不一致，先检查缓存，不触碰其他实例。

年末清算会在 12 月 31 日 23:59:00 由 008 定时器触发，队列记录固定的旧积分年度窗口。定时器按秒匹配，必须监控该分钟是否真正派发；按年度预估会员逐人核对 `eb_user_integral_expiry` 和 `system_clear` 积分流水。队列默认最多尝试 3 次，失败任务可能被删除，应监控失败日志和缺口，按原固定窗口只补未完成 UID。2026 年末的积分数可因启用后新增消费或积分调整变化，启用时的预测不是结算保证值。

## 暂停和回滚

若尚未发生清算，需要暂停时，先确认连接仍是 `mohe_008:3307`，在事务中对启用标记中的定时器 ID 设置 `is_open=0`，并把 `integral_effective_status` 改为 `0`；保留年度类型、启用标记及审计记录。随后只在 008 Redis DB 0 调用 `SystemConfigService::clear()` 与 `SystemTimerServices::setAllTimerCache()`，再通过只读查询和运行时配置核实。正式恢复时应形成新的受控启用版本；不要直接重跑旧 `apply` 绕过已暂停状态。

若已有到期扣减，先停定时器并暂停消费相关任务，再逐会员比较余额、清零流水及守卫记录。恢复积分需要可追溯的反向积分调整与专项对账，不能删除守卫表、清零流水或只回滚代码。通用结构升级只有在幂等表为空、未启用且无队列任务时才可考虑撤销。
