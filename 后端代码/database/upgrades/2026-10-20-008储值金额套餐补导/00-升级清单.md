# 008 储值金额套餐补导

## 业务范围与原因

- 008 的后台储值金额页面调用配置组 user_recharge_quota 时，目标库缺少父组和明细，表头与列表接口返回 HTTP 500。
- 旧渼约 morestore 中该组为 ID 62，现有 13 个档位，其中启用 4 个、停用 9 个。启用售价分别为 1000、2000、3000、5000 元，启用赠金均为 0 元。
- 本批只补 1 个配置组及 13 个金额档位，逐项保留原 ID、金额、排序、创建时间和启停状态。会员现有余额、历史充值、订单及赠金流水不在范围内；不触碰其他客户实例。
- 旧站本批档位没有储值赠品缓存配置；008 若已出现赠品关联，执行器停止，不自动覆盖。

## 固定来源与守卫

- 来源实例：旧站本机 MySQL 3306，数据库 morestore；目标实例：008 本机 MySQL 3307，数据库 mohe_008。
- source-snapshot.json 固定旧组和全部 13 条档位，SHA-256：61972c1a162993b31e8569d508a618e1a1cc6a65bb518248a7ead30895f9994f。
- 执行时重新逐字节比较旧库数据与快照。旧库变动、目标已有同组/同 ID 局部数据、赠品关联或审计冲突时立即停止。
- 所有金额按整数元校验。保留 9 个停用档位的停用状态，避免旧优惠重启。
- 一笔 InnoDB 事务写入父组、13 条明细和升级日志；重复执行拒绝，失败回滚。提交后仅删除 008 Redis 的该配置缓存键。缓存删除失败时可独立重试。

## 自测和上线验证

- PHP 语法与 SQLite 合同测试：快照字段约束、完整行集、4 条启用/9 条停用、重复导入拒绝、局部冲突无写入。
- MySQL 5.7 隔离库演练：同一执行器完成事务写入、逐行核验并销毁隔离库。
- 线上执行前：核对唯一源码正本 HEAD/本批文件指纹、008 当前入口与相关文件指纹、旧库数据、008 目标空表及升级日志，确认产品经理对固定版本验收和 008 写入授权。
- 线上执行后：核对 1 个父组、13 个档位、4 条启用、9 条停用、升级日志；重新请求 008 表头与列表接口，打开页面检查 4 个启用金额可见、添加表单可用且无服务器报错。核实相关既有页面入口仍可打开。

## 执行与回退

- 执行器默认 check 只读；apply 必须提交已验收脚本及快照 SHA 和本地提交号；verify 只读。服务器用目标站的 PHP CLI 运行，执行日志不得打印连接密钥。
- 执行前保存目标两张表中涉及的行及目标升级日志的查询结果作为逐行回滚点；目标预检应全部为空。
- 如数据库写入中失败，事务自动回滚。如提交后页面仍异常，先检查 008 缓存与接口；确需回退时在 008 专属事务中仅删除本批 13 条明细、父组 ID 62 和升级标记，且必须先验证数据仍与固定版一致、没有新充值或人工改动引用这批档位。删除后仅刷新 008 对应缓存。
- 本批未改共享业务代码；代码提交仅含此目录和对应合同测试，禁止夹带其他任务改动。正式执行结果另记实际时间、目标指纹与业务验证证据。
