# 目标方案逐行生效

## 范围

唯一生效身份为租户、报表、门店、月份、指标、对象类型、对象 ID。
仅迁移当前有效的绑定；不激活历史草稿或作废方案，不修改任何交易事实。
旧 target_report_binding / target_effective_line 保留为升级时恢复资料，新代码不再读写，禁止双写或回退读取。
删除使用方案状态 deleted，历史明细、作废原因与操作审计保留，但列表、详情、编辑和生效入口不可再访问。

## 执行

初稿只授权本地准备和测试。2026-10-20 产品经理验收后授权“本轮 commit → 瑞昊 → push → 渼约008”；发布仍须逐实例重新核对基线并独立导出全部目标方案相关表，恢复验证通过才可迁移。
暂停所有平台和移动端的目标方案写入，确认所有写入服务可同步切换，先运行 01-前置检查.sql，异常为零才执行 02-正式升级.sql。
该 SQL 是一次性升级，不可重复执行；执行中断须按备份与实际表状态恢复，不可盲目重跑。
迁移前后按 tenant/report/store/month/metric/scope/line_id/target_value 全量对账，而非只核对行数。
运行 03-升级后验证.sql 并完成逐行对账，通过后切换后端与平台前端；旧客户端遇到冲突会收到明确错误，不能未经确认替换。
完整冲突清单最高 21000 条，回执与审计列扩展为 MEDIUMTEXT；不改历史文本内容。部署前核对数据库 max_allowed_packet 足够容纳最大回执。
最大冲突 JSON 实测 5,088,663 字节，发布门禁取至少 16MB。008 当前为 4MB，产品经理另行明确批准仅将其独立 3307 数据库参数提高到 16MB 并持久化；不改 007/012 或共享实例。

## 回滚

未发生新写入时，可以停写后回退代码并移除本次新建投影表；旧表保持原样。
已经产生新写入后，旧结构无法表达多月份并存，禁止仅回退代码；须停写、独立导出新增操作审计，
经明确授权恢复升级前全套目标方案表并登记之后操作的补录方案。不得直接拿陈旧绑定覆盖新结果。
