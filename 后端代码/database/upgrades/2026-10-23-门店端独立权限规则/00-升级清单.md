# R28 门店端独立权限规则

## 最新补充：导航层级

目录补齐34个不可授权导航入口（22报表、9订单分类、2账号操作、1会员领用），共91项：51业务编号、6大类及34导航入口。入口仅控制显示，业务鉴权仍用原功能码及数据范围；岗位授权树不包含这些纯展示节点。

03-初始化.php 最后显式执行 initializeNavigationItems，只补缺项并记录配置前后审计；重复执行不覆盖现有编辑或改动岗位记录。首次安装随大类一起初始化，普通读取不写库。回滚继续按配置审计和本实例备份有条件恢复，不回滚业务事实。

## 范围与权威源

- 门店端功能身份、可执行路由与业务祖先固定在源码白名单；数据库目录只保存名称、显示层级、排序、启停及编辑修订号。
- 岗位仍使用 `job_position_channel_rule.channel=store_v3`，员工任职及数据权限范围沿用现有权威链，不新增个人授权体系。
- 平台新增「设置 → 权限设置 → 门店端权限规则」，维护资格复用原权限规则管理资格，也支持单独授权新增平台菜单。平台/商家端岗位记录不改写。
- 业务事实、金额、订单、余额、核销、会员所属门店均不变；配置修订号不进入收银唯一业务快照。

## 执行顺序（仅对另行点名授权的实例）

1. 核对唯一源码版本、实例数据库、表前缀和最低 MySQL 版本，备份 `job_position_channel_rule`、`system_menus`、新目录/审计及升级日志表。未上线前保持客户实例不变。
2. 在暂停岗位权限配置写入的维护窗口先执行 `02-正式升级.sql`，然后由该实例的 PHP CLI 执行 `03-初始化.php`。不得在普通请求或查询中隐式升级。
3. 初始化器在实例内互斥并事务迁移，逐行保存原规则审计；只展开 `store_v3`，稳定编号保留。新能力按原共用权限继承；原有旧数据录入的显式授权要求保留。
4. 多岗位组合若存在旧父级默认逻辑歧义导致权限变化，初始化器会整体回滚；必须核对具体任职后再决定，不能绕过检查。
5. 同一初始化器显式补齐6个不可授权的菜单大类；目录保存为51个业务节点加6个大类。订单管理初始位于运营管理右侧，订单归入订单管理，费用归入运营管理；空财务管理不在门店顶部显示。已有目录只升级展示元数据并保留审计，不重新展开岗位；普通读取不写库。菜单归属补充升级以 INITIALIZE_ORDER_NAVIGATION 审计作为幂等标记，重复执行不覆盖后续管理员编辑。
6. 初始化器重复执行不重新展开新规则、不增加重复迁移审计。升级日志 key：`20261023-r28-store-permission-catalog`。
7. 部署同一固定源码的后端、18081 平台端、18091 门店端对应集成包，重载目标后端，逐入口验证岗位保存、目录读写、导航、深链接及接口权限。

## 恢复边界

切换前失败可恢复代码及备份规则；上线后已经发生新的岗位/目录编辑，不可整表覆盖。先保留新审计，再按此次迁移的逐行 before/after 和备份有条件恢复，避免覆盖后续合法修改。不会回滚收银或其他业务事实。
