# R31 瑞昊 26 张基础报表归入「数据 → 日常运营」

## 本轮边界

- 010 仅用于只读核对目录，原站菜单、岗位、业务数据均不修改。
- 瑞昊正在运行的统一报表目录已注册 26 张；平台共用的 Vue 3 页面和后端查询能力已存在，本轮只做瑞昊菜单配置，不部署旧构建或另一套报表代码。
- 瑞昊现有 22 张菜单保持 `id`、`unique_auth`、逐表授权及报表 URL 不变，仅移动到「数据 → 日常运营」。缺少的销售数据、PK数据、销售分析、门店效能 4 张按当前统一目录新增菜单，并仅给原已获「门店统计」权限、且已有「日常运营」父菜单权限的岗位追加这 4 张权限。
- 迁走后原「门店统计／员工统计／其他报表」分组仅在没有其他可见子菜单时隐藏；不删除菜单或岗位授权，避免破坏历史引用。
- 不读取、复制、迁移或修改两站任何报表业务事实。此变更不影响指标口径、事实粒度、统计日期、冲销、下钻或导出数据权限；后端继续按登录人的组织／门店范围裁剪。

## 验证和生产执行门禁

1. 当前 Git 基线、两站现网入口、瑞昊菜单／岗位及运行中 26 张目录必须先只读核对；若现网已变化，重新预演，不覆盖较新的配置。
2. 本地 `php -l`、`--dry-run` 和 `--test-rollback` 通过；预演要求首轮 4 张新增、22 张迁移、最终 26 张直挂、旧空分组隐藏，重复执行不新增菜单且测试事务回滚后原状态不变。
3. 产品经理对固定文件指纹明确确认验收后，再精准提交本迁移；执行前对瑞昊 `ruihao` 独立创建当时的数据库备份并记录校验值和回滚点。不要沿用此前备份。
4. 从已提交的迁移源执行：`cd /www/wwwroot/rh.cc3798.com && php /dev/stdin --dry-run < 01-执行.php` 可只读预演；正式执行须 `--apply --backup=/www/backups/rh.cc3798.com/<批次>/ruihao-before.sql.gz`。不得对 010 或其他客户执行。
5. 执行后核对 26 个唯一菜单、父链、排序、岗位授权及三个旧空分组；使用有权限的瑞昊账号实际打开 26 张页面并验证查询、导出权限及至少一张原有报表回归。若本轮只批准菜单、未批准业务数据操作，真人测试只读取数据、不产生写入。
